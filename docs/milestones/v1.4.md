# v1.4 — free-standing peaks

**Opened 2026-09-12** (version → `1.4.0.dev0`), thirteen days after v1.3
shipped. The slot was first opened for v1.1 and shifted three times
(2026-08-20, -25, -28) with its numbers kept; [`../ROADMAP.md`](../ROADMAP.md)
§ v1.4 carries that history and the three WPs.

## Scope

Peaks without a structure — fitted standalone at positions a caller names
(1101), and the `Instrument.extra_components` union seam with broad humps
(1102) and sharp peaks (1103) as its first two members. Each WP file states
its own context and baseline; nothing is restated here.

## Acceptance

**These rows are written at the open**, which is the whole point of protocol
rule 6: the [v1.3 record](v1.3.md) says plainly that rows written at ship are
the weaker evidence, because a row written after the fact cannot fail. Each
names a state a later session can check without asking what was intended.

The 1101 rows are stated in full because that WP is open. The 1102 and 1103
rows are stated at the level `../ROADMAP.md` already commits to, and the
session that opens each WP sharpens its own row here — a bar set by someone
who has not read the WP is a bar set too low.

- **A caller can fit exactly the peaks they name** (1101). `fit_peaks(data,
  instrument, positions)` is a documented top-level call returning a
  `PeakList` whose components in each window are the caller's positions and no
  others, and `capabilities()["features"]["peak_fitting"]` is derived-True —
  derived from the export's existence, not written `True` (WP-1037's rule).
- **A named position that fits nothing is answered, not dropped** (1101). The
  chapter states what `fit_peaks` returns for a position where there is no
  peak, a test pins it, and the answer is neither a silent drop (the version
  this WP tried first, which made the GUI's add verb do nothing) nor an
  unflagged component wearing an ordinary esd.
- **A named position beside an unnamed real one says so** (1101). Fitting the
  caller's model alone where detection saw more biases the named position, and
  the only numeric trace is χ²_red; the affected peaks carry a flag of their
  own. Evidence, not refusal.
- **One window-sizing arithmetic, three callers** (1101). Detection, the GUI
  peak editor and `fit_peaks` size a fresh window through one helper in
  `indexing/`; `gui/` imports it back, and `tests/test_gui_peaks.py` is
  unchanged-green across the lift.
- **Williamson-Hall is a computation the manual executes, not a helper the
  package ships** (1101). The numbers in the chapter come from an executed
  block over a real `PeakList`.
- **The component seam is one serializable union** (1102). An instrument
  carrying extra components round-trips through JSON and back, and a hump is
  the first member rather than a special case beside the seam.
- **An old file opens and still refines what it refined** (1102, sharpened at
  the open 2026-09-13). `Instrument.background_peaks` shipped in v1.2 and is
  spelled into history JSONL, into a `.rex` project's stage globs and into
  `.rxt`. A project saved by 1.2 with a declared peak opens after the rename
  **and its plan still frees that peak** — the glob is migrated on read, not
  only the value, because a glob that matches nothing is the silent failure and
  a missing field is the loud one. A test pins both halves. Assigning
  `instrument.background_peaks` in *code* raises, and the break is recorded.
- **The contract admits an expression member and fences only the callable**
  (1102). The union's docstring states what a member owes, and states it so a
  future member holding serializable expression text is admissible under it —
  TOPAS's architecture, not a Python callable. Checkable without running
  anything: the three grounds this WP first gave for fencing a DSL are each
  answered in the contract, or the row fails.
- **The seam is visible to a client** (1102). `capabilities()` carries a derived
  arm for it, derived from the export's existence with the name held as data in
  `_SURFACE_FLAGS`, never written `True` (WP-1037's rule).
- **What the union has not yet proved is written down** (1102). The contract has
  two axes, evaluator shape and where a member lands; `HumpComponent` alone
  tests neither against a second case. The WP says so in as many words, and 1103
  is named as the proving case for the second axis. A one-member union that does
  not admit this is a failed row, not a passed one.
- **A sharp extra peak is the same seam's second member** (1103, sharpened at
  the open 2026-09-13), costing no new field on the union. `PeakComponent`
  joins `ExtraComponent` by existing: `capabilities().extra_component_kinds`
  reports it with no list edited, and the cross-backend `CONFIGS` matrix, the
  manual equation with its `*Source:*` line and the `help.py` entries all
  arrive with it, because each of those has a test that fails without them.
- **Clause 2 of the member contract stops being a design intention** (1103).
  A member's aggregate membership is held as **data**, never read off the
  class name — the hump joins the reported background, the peak joins the
  tick list. The 1102 row above says in as many words that one member tests
  this against no second case; this row is that second case, and it is passed
  only if a test would go red were the membership inferred from the class
  rather than declared. If the clause could not be honoured and was changed
  instead, the change and its reason are written down — an unhonoured clause
  left standing is a failed row.
- **The operando case is measured end to end, and the alternative is quoted
  rather than forbidden** (1103). Holder lines injected over a standard's
  peaks, refined with the components declared, land the cell within a stated
  tolerance of the clean-pattern cell; the `excluded_regions` alternative's
  cell **and** its lost-channel count are reported beside it. No code path
  refuses or gates a declared component anywhere in the WP — evidence only,
  which is checkable by grep as well as by test.
- **A free centre cannot leave its frozen window, and η is part of why**
  (1103). Windows are sized from `center`'s bounds and `k(η)` at η's *upper*
  bound, so the frozen-per-stage invariant holds with no `free_paths=`
  plumbing and with no fixed ±30 FWHM reintroduced. A test drives a centre to
  its bound and it is still inside. A window holding zero fitted channels is
  refused at compile naming the peak, in the `check_interval` sentence shape.
- **A declared peak that is not in the specimen says so by an absent esd**
  (1103). Not by an Rwp comparison, which the package forbids as a
  correction's evidence; the equilibrated covariance (1110 item 14) is what
  makes the honest answer available, and the wording is the peak list's
  existing `no_intensity` rather than a second vocabulary for one fact.
- **A holder line the user declared does not become phase intensity** (1103).
  Under Le Bail and Pawley the component curve joins the **subtraction** side
  at both seams and never the denominator, pinned by a test in which a
  declared synthetic holder line leaves the extracted phase intensities
  unbiased. Peak components stay refinable in those modes, which is why the
  intensity field is not called `scale`.
- **A threshold ships only if this WP measured it** (1103). The 0.25
  background-absorption threshold was measured for background blocks and
  nothing has measured component blocks, so `extra_peak_absorption` ships
  evidence-only unless the acceptance measurement supplies a separation —
  and the measured separation is recorded in the WP either way, including
  when it is the argument for shipping no threshold.

## Additions this milestone makes, for the release notes

Kept beside the breaks and for the same reason: written as each lands, not
reconstructed at ship.

- **`fit_peaks` — fit exactly the peaks you name** (1101, 2026-09-13), with no
  model at all. `rx.fit_peaks(data, instrument, positions)` returns a
  `PeakList`; a named position where there is no peak is *answered* rather than
  silently dropped, and a named position beside an unnamed real one is flagged.

- **`PeakComponent` — declare a sharp peak your phases cannot account for**
  (1103, 2026-09-13). A sample holder at its own specimen distance, a mount, an
  unidentified impurity line: declare it and the channels stay in the fit
  instead of being excluded along with the sample peaks underneath.
  `SCHEMA_VERSION` 0.18 → 0.19; no break, since the field is the list 1102
  already added and an absent component is exactly off.

  *Who has to do something:* nobody. *Who may want to:* anyone who has been
  excluding regions around an intruder that overlaps peaks they care about.

  It joins `Instrument.extra_components` as the union's second member, and the
  difference from a hump is where it **lands**: a hump is reported background,
  a peak joins `result.ticks` under the reserved key `"(extra)"`, which is what
  stops Layer 0 calling a declared peak an unindexed impurity. Under Le Bail
  and Pawley its curve is subtracted from the partition net, so phases are not
  handed a holder's counts — and it stays refinable there, which is why the
  intensity field is `area` and not `scale`.

  Two new diagnostics, both advice and neither a gate:
  `EXTRA_PEAK_ON_REFLECTION` (the component sits on a line the model already
  predicts — a degeneracy, legitimate when the overlap is real) and
  `EXTRA_PEAK_NO_INTENSITY` (the area refined to zero, so the centre is not a
  measurement). `Identifiability.extra_peak_absorption` carries the
  block-projection number beside them, reported and deliberately not
  thresholded.

  *What it is measured to do, and what it is not:* on the SRM 660c protocol
  with two holder lines injected onto reflections, declaring them recovers the
  clean-pattern cell to −1.0 ppm where ignoring them costs +7.6 ppm and
  inflates the cell esd 7.5×. **Excluding the regions instead also recovers
  it**, to +0.6 ppm, for 4.8 % of the channels — so on a pattern as
  reflection-rich as LaB6 the gain is the retained channels and a measured
  intruder, not cell accuracy. The gain grows as the reflection count falls,
  which is the operando case the feature was designed for.

- **Every fit records itself** (1403, 2026-09-15). `Refinement.fit`,
  `run_stage`, `refine` and `refine_sequential` write a run directory without
  being asked: the event log, a per-stage `snapshot.json`, `summary.txt`,
  `meta.json`, `status.json` and a held `run.lock`. `rietx watch` lists them and
  draws them. 204 kB for a five-stage synthetic LaB6 fit, `[dev]`, macOS arm64.

  *Who has to do something:* anyone fitting on a shared filesystem who does not
  want a parameter trajectory left behind, and anyone whose working directory is
  somebody else's repository. `RIETX_TELEMETRY=0` switches it off for a process,
  `telemetry=False` for a call, `telemetry=<path>` moves the root, and a
  `.gitignore` of `*` goes into the root so runs stay out of `git status`. *Who
  does not:* anyone who wanted the watcher to have something to show, which was
  previously conditional on remembering to pass `events=`.

  *Why it was worth making:* WP-1322 measured three of three subagents switching
  telemetry off, and WP-1401 then measured the cost at 1-3 % of a fit, so the
  knob nobody had to switch on is the one an agent cannot switch off by
  accident. Every configuration returned a bit-identical Rwp: recording does not
  change the answer.

  *What it deliberately is not:* a `capabilities()` flag, because "can this
  build record runs?" always answers yes and the flag would be a literal `True`;
  and a seventh versioned contract, because nothing negotiates over the layout
  yet. `runs.py`'s module docstring holds both refusals, and
  `using/compatibility.md` states the second one to a reader.

- **The recorder is written so that telemetry cannot break a fit** (1403). Every
  recorder method latches one-shot on `BaseException`, records why in
  `status.json` and warns once a process. A callback you passed through
  `events=` is yours and still runs outside every try block, so a monitoring
  hook that crashes the refinement is still a bug you get to see.

- **`read_gsas_prm` reads a Kα1/Kα2 doublet** (1118, 2026-09-15). A `.prm`
  stating two wavelengths comes back with two emission lines, the second
  weighted by the file's own `KRATIO`. It used to be refused, and the reason
  given was that no file here stated the intensity weight — which was an
  artefact of reading the record by splitting on whitespace, where `KRATIO`
  could not be told from the polarization two fields along. Both are
  conventionally 0.5.

  *Who has to do something:* nobody; a single-wavelength `.prm` reads exactly as
  before, bit for bit on all four real files in `tests/data`. *Who may want to:*
  anyone who read a lab `.prm` and added the Kα2 line by hand afterwards.

  The record is now read by column, through the grammar
  `io/projects/gsas.py` holds and the `.EXP` reader was already using. Two
  readers parsing one record is how they come to disagree about it.

## Breaks this milestone makes, for the release notes

Four. Recorded here as each lands rather than reconstructed at ship, since a
break written up from `git log` months later loses the reason it was worth
making. The last two landed after v1.4 shipped, which is where a break goes when
no milestone is open (ROADMAP § Session protocol, step 6).

- **`Instrument.background_peaks` → `extra_components`** (1102, 2026-09-13),
  with `BackgroundPeak` → `HumpComponent`,
  `RefinementResult.n_background_peaks` → `n_extra_components`, and the
  `BACKGROUND_PEAK_*` constants and the `BACKGROUND_PEAK_TOO_NARROW` diagnostic
  to `HUMP_*` / `HUMP_TOO_NARROW`. `SCHEMA_VERSION` 0.17 → 0.18.

  *Who has to do something:* anyone whose code assigns the old attribute or
  matches on the old diagnostic code. *Who does not:* anyone with a saved
  project, history tree or `.rxt`. Those open unchanged, **and their saved
  plans still free the hump they froze** — `rietx.schemas.migrate` repairs the
  stored dot-paths as well as the field, because the two halves fail
  differently and only one of them fails loudly.

  *Why it was worth making:* the field was a `list` of one concrete class, and
  every code that ships this capability carries several kinds of additive
  non-Bragg term at once (GSAS-II, FullProf, TOPAS — 1102 § The seam decision).
  The rename is what lets 1103's sharp peak be a member rather than a second
  field with the whole wiring duplicated behind it.

  Two spellings were held still deliberately: GSAS-II's own CSV column name in
  the PowderLine reference data, and `RECIPE_BACKGROUND_PEAK_DEGENERATE`, whose
  `RECIPE_` prefix marks it as a statement about a foreign document.

- **The `AGENT_PROTOCOL.md` pointer is deleted** (the ship pass, 2026-09-13),
  as [1304](../wp/1304-protocol-as-skill.md) kept it for one release and the
  file itself promised. Two paths stop resolving: `rietx/data/AGENT_PROTOCOL.md`
  inside the wheel, and `https://rietx.org/AGENT_PROTOCOL.md`, published since
  v1.0.

  *Who has to do something:* anyone reading either path for the refinement
  protocol. It is the agent skill — `rietx skill --path`,
  `capabilities().skill_path`, or `https://rietx.org/skill/rietx/SKILL.md` —
  and the section numbers are unchanged, so a citation of §7d still resolves.
  *Who does not:* anyone calling `rietx skill` or reading the skill, which is
  every route the package itself documents.

  *Why now rather than never:* the pointer's whole job was to make the 1.0-1.2
  path resolve for one release rather than 404 mid-upgrade, and a forwarding
  stub that outlives that is a second answer to "where is the protocol"
  competing with the real one. The **site** copy was the fourth site and the
  one the WP's own scoping missed (`pages.yml` copied it to the site root);
  the links reaching it from four shipped milestone records were repointed at
  the skill rather than dropped.

- **`LiveSession` stops writing `fit.html`** (1402, 2026-09-15). It writes
  `snapshot.json` — the stage's decimated curves, ticks and statistics — and
  `rietx watch` draws them. `runs.SNAPSHOT_FILE` is that file now;
  `runs.LEGACY_SNAPSHOT_FILE` is the old name and `Run.has_legacy_snapshot` the
  flag beside `has_snapshot`.

  *Who has to do something:* anyone whose own code opens
  `<live-dir>/fit.html` after a run, or implements `write_snapshot` on a custom
  `events=` object and expects a page to appear. *Who does not:* anyone
  watching a run, since a `fit.html` already on disk still opens and is still
  served both at `/api/run/<id>/legacy` and by its bare name; and anyone
  calling `rietx html` or `viz.html.write_html`, which are untouched. The
  self-contained emailable page remains a capability; what stopped is producing
  it unasked.

  *Why it was worth making:* the page was built on the fit's own thread, so
  every stage stopped to serialise the whole of plotly afresh — 4.51-6.03 MB
  against the 180-329 kB the numbers take, and 1.04-1.49x a bare fit's wall
  clock against 1.03-1.28x now. It also lost the reader's zoom at every stage,
  precisely when they were looking at something, and it made recording a run
  impossible without plotly installed, because building the figure was how the
  view was stored. `LiveSession` is public, so this is the largest public
  change in the live-watcher track.

- **A project's `live/` holds one directory per run** (1403, 2026-09-15), where
  it held one event log. The path is `live/<run id>/events.jsonl` now.

  *Who has to do something:* anyone whose own code opens
  `<project>.rex/live/events.jsonl` by that path. *Who does not:* anyone opening
  a project, since `project.json`'s schema is untouched and an existing `live/`
  log still resolves as a legacy run that `rietx watch` lists forever; and
  anyone using `Project.live_dir`, which still names the same directory.

  `PROJECT_FORMAT_VERSION` did **not** move, decided deliberately rather than
  overlooked: `live/`'s contents were never part of the format's promise, and
  the schema the version string covers is unchanged.

  *Why it was worth making:* a GUI session and an agent fitting the same project
  interleaved their events into one file, so neither could be read back. One
  directory per run is what separates them, and it is the shape the runs root
  outside a project already had.

### 2026-09-16 — a page that holds still

WP-1423 is unscheduled and is recorded here because it landed after v1.4 shipped
and no milestone is open. It is a user-facing change to `rietx watch`. The run
list and the selected run were two pages and are now two panels of one, either

page no longer moves between polls: the list is patched in place under declared
columns, the status line is a strip of fixed slots, and the plot's 2θ and

status file now records which pattern is being fitted, four new optional

new run every 18 s. Before, over 25 s at 1400×900: 21 rebuilds of the run

intensity range per pattern, three rungs on Δ/σ.

### 2026-09-15 — what recording every fit costs, and where

WP-1404, the measurement WP-1403 was shipped ahead of. Recording every fit is a
tax on people who never asked for it, so the track carried a WP licensed to send
1403 back, with its gate and its three failure paths written down before any
number arrived. The gate was 1.05×, widened on any case whose own repeat spread
was wider.

**The shipping default costs 1.03 to 1.28×, and it fails that gate on two cases
of three.** `nac` 1.279× against a widened 1.059×, `cpd-2` 1.075× against 1.050×,
`trigger` 1.030×. `[dev]` venv, macOS arm64, seven interleaved repeats a
configuration. `nfev` and Rwp were identical across all five configurations on
every case, so recording still changes no number, and three counted assertions in
`test_telemetry.py` now hold that.

The failure is not where the WP looked. It had named the per-evaluation
`_free_values` decode the dominant term, and the decode is 4 to 16 % of the bill.
The per-stage snapshot is the rest. Two independent measurements say so: a
caller's own `events=<path>` buys the entire event stream for 1.005 to 1.012×,
and a scaffold that drops the stream *and* stubs the decode lands within noise of
the full recorder on all three cases. So WP-1403's first two mitigations are
withdrawn, each worth at most 1.2 % of a fit, and the appeal of the one that
looked free was that nobody had priced it.

What the cost actually is: **16.7 to 21.9 ms a stage**, barely moving across a
factor of 16 in fit length. The ratio therefore orders by how long the fit runs
and not at all by how big the pattern is, which is the question WP-1406 raised
and left owed. `nac` carries the most points, finishes in 0.357 s, and pays the
worst ratio of the three.

That also discharges WP-1406's conditional the good way. Its manual page and the
skill's § 9d.7 quote 1.03-1.28× from the `LiveSession` path, as the nearest
measured proxy for a recorded fit. The recorded fit measures 1.03 to 1.28×, and
`live` and `record` land within 0.02 of each other on every case, because the two
do the same per-stage forward work. Neither figure changes. A recorded run is
358 to 534 kB on these cases against WP-1403's 204 kB on five-stage LaB6.

**The decision was to keep recording on by default and cut the snapshot instead**,
which is [WP-1413](../wp/1413-the-snapshot-is-what-recording-costs.md). The
absolute cost is about 20 ms a stage, which is under 3 % of any fit a person
waits for, and the 1.28× row is a 0.357 s benchmark leg. The lever is
`decimation_index` at 6.6-7.1 ms of that, under WP-1402's constraint that a
faster decimation return a bit-identical index set.

The session's other finding is about instruments rather than telemetry. The first
run of the matrix ran every repeat of one configuration before starting the next,
and produced `events=<path>` at 0.816× a bare fit, which is faster than not
recording, and a recorder cheaper than the event stream it contains. Blocked
repeats give each configuration a contiguous slice of wall clock, so machine
drift lands on one of them entire; the control's own spread was 11.4 % and 13.2 %
saying exactly that. Interleaving inside each repeat brought it to 1.1-5.9 % and
the impossible orderings went away. WP-1405 had already reached that shape from
the other end, interleaving the arms of one fit to price a cancel token, which is
why its 1.0036× is the finer number. The harness now carries the reason at the
loop, and a min-of-N column beside the median, because two estimators of one
quantity that disagree are still measuring the box.

### 2026-09-15 — the window gets a verb, and it is stop

WP-1401 built a window onto a running refinement and gave it deliberately no
verbs, on the argument that a reader cannot click what is not there. WP-1405 is
the one exception that argument always anticipated: a person watching a runaway
could see it and had nothing to do about it except go and find the terminal the
fit was started from.

The seam is a file, because the two processes already share a directory and
nothing else. It carries a *request* rather than a flag, so the next
intervention verb is more words in one file, and a request naming a word this
version does not know is declined by name instead of being rounded to a cancel
— an old install meeting a newer watcher's `pause` must not stop the fit.

Two things this cost, both decided on measurement rather than on taste. A
recorded fit now always carries a cancel token, which ends the promise that an
ordinary fit pays nothing for the abandon-and-restore machinery; the price was
measured first at 1.0036x on the three-stage synthetic fit, with both components
bounded separately so the claim holds away from that one case. And stopping
ships enabled, with `--read-only` to decline it, because the server binds
127.0.0.1 and the only person who can click already has Ctrl-C into the same
process — a flag you must set in advance is not set when a runaway starts.

The sharpest fact in the whole track is that a browser click raises an exception
in somebody else's process, and a script that does not catch it prints a
traceback. That belongs in the dialog rather than a docs footnote, so the dialog
says it in as many words, takes two clicks and has no keyboard shortcut.

the browser's own rule for a hidden element, so the *closed* dialog was an
invisible sheet over the whole page swallowing every click, including the one
that opens it. A python test asserting substrings of the page could not see it
and neither could `node --check`. It took a real browser and a real click.

### 2026-09-13 — a vendor format that lies about its own intensities

WP-1407 is unscheduled and is recorded here because it landed while v1.4 was in
flight, not because the milestone claims it. It added PANalytical `.udf` and
Philips `.rd`/`.sd` plus three refusals, and one thing in it generalises past
file formats.

The `.rd` intensities are **square-root compressed**. Read the obvious way —
the way the only permissively-licensed description of the format reads them —
every peak lands in exactly the right place and every intensity is wrong. There
is no symptom: the profile looks like a diffraction pattern, the fit converges,
and Rwp is whatever it is. This is the failure mode WP-1047 named when it
refused Bruker `.raw` v2 on "one uncorroborated description and no file", now
observed rather than anticipated, and with the twist that the *permissive*
source is the defective one. A licence says what may be copied; it says nothing
about what is right.

What broke the tie was an oracle rather than a second opinion. The IUCr CPD kit
publishes the original logged `.rd` scans **beside** the ASCII conversions this
repository has committed since v0.3, so the reader can be checked channel for
channel against a file already in the tree — and is: 15 of the 16 reproduce bit
for bit, and the sixteenth differs by exactly one count on 2108 channels because
the kit converted that one file with a different rounding rule. The previous
session had planned around those files being gone. They were behind a
Cloudflare challenge.

Two rules came out of it and live in `io/CLAUDE.md`: check a description against
a file before believing it, and reach for the format's own redundancy as the
gate — `.rd` states its length twice and its maximum once, `.udf` states its
point count two ways, and each disagreement is refused rather than repaired.

### 2026-09-13 — the seam gets its second member, and the comparison is honest

1103 closed the day 1101 and 1102 did, which is not a pace to read anything
into: all three were designed together in one planning session and 1102's seam
was built knowing exactly what would land in it.

What the day actually settled is narrower than the milestone's scope and worth
keeping. The component union's member contract had two axes — an evaluator's
shape, and where the member lands — and the second is now tested against a real
second case: a hump joins the reported background, a peak joins the tick list,
and the destination is read from data rather than inferred from a class name.
The first axis is still an intention; a Debye term would be its proving case
and nobody is holding one.

And the measurement refused to flatter the feature. The design case was
"excluding the region masks the sample peak underneath, so declare the intruder
instead" — and on real SRM 660c data with two holder lines injected onto
reflections, excluding recovers the cell just as well as declaring (+0.6 ppm
against −1.0 ppm), for 4.8 % of the channels. Both beat ignoring the intruder,
which costs +7.6 ppm and inflates the cell esd 7.5×. So the feature's case is
the retained channels and a measured intruder, not accuracy, and it strengthens
as the reflection count falls. That is written into the acceptance module, the
release notes and the agent skill, in preference to a table that reads as a win

### What the ship pass found

Six things, none of them in the code, and each one a class rather than an
incident.

**A deletion scoped from a record is scoped from memory.** The milestone record
named three sites for the `AGENT_PROTOCOL.md` pointer: the file, the wheel
force-include, and the links in four shipped records. There were four. The
fourth was `pages.yml`, which copied the file to the site root, so
`https://rietx.org/AGENT_PROTOCOL.md` — published since v1.0 — would have
outlived the deletion as a stale document rather than a 404. A grep found it in
one second; the scoping paragraph had been written from what the session
remembered building. **Scope a deletion with a grep, then write the paragraph.**

**A release covers the tag range, and a milestone record covers the milestone.**
Sixty-three merges separate the v1.3.0 tag from this tree and three of them are
v1.4 WPs. Two consequences the record could not see. `report_thresholds_version`
moved 1.4 → 1.5 (WP-1131's `FitReport.microstructure`), so **two** contracts
moved this release and the milestone knew about one. And the `Atom` bounds
change of issue #204 is a **construction break** — `Parameter(value=-165.0)` for
`biso` used to store and now raises — shipping with no entry in any milestone
record's Breaks section, because it landed after v1.3.0 shipped and a shipped
record is closed. Both are in the notes. The durable fix is cheap: **a break
landing between milestones belongs in the open record's Breaks section on the
day it lands**, and when no milestone is open it belongs in the last shipped
one, exactly as rule 5 already routes the narrative.

**A parked entry is a claim about the tree and rots like any other.** The
always-loaded ROADMAP carried "the LaB6+cBN correlation test's Linux-only red,
never green there" for eleven days after it stopped being true: 42161a06
narrowed the bar to the phase broadening terms on 2026-09-02, and the Linux
nightly has been green since. A parked item is exactly where nobody looks, so
**parking needs a re-check at the ship, not a memory.**

**The README and the landing page lag the readers.** Both format lists stopped
at `.xrdml`, two reader WPs ago, and neither named `fit_peaks`, declared
components or the model-file readers. Rule 6's "check README's claims" caught
it; nothing else would have, because no test asserts that a feature list is
complete — and one probably should not, since the list is a judgement about
what a reader needs first.

**A cap with 20 bytes of headroom is a cap that fires on the next change.**
`docs/skill/rietx/references/diagnostics.md` is 35 980 B against 36 000. The
two diagnostics this milestone added are in it; the next one does not fit, and
issue #287 asks exactly this question with PR #291 proposing an answer. Left to
the maintainer, and named here so the next session does not discover it at the
moment it is adding a row.

**The version lives in three places and reinstalling is one of them.** Carried
from v1.3's ship pass and cost nothing this time because it was written down:
`pyproject.version`, the editable reinstall that rewrites dist-info (since
`rietx.__version__` is `importlib.metadata.version`), and the skill's
`metadata.version` with its two committed copies re-synced.
