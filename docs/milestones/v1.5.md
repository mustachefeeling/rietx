# v1.5 — a window into a run

**Opened 2026-09-18** (version → `1.5.0.dev0`), four days after v1.4.0 was
tagged and **496 commits after it**. This is the first milestone in the
repository opened *behind* its own work, and the Acceptance section below says
what that costs.

## Scope

Twenty-six WPs with commits in `v1.4.0..main`, every one of them opened
unscheduled. `../ROADMAP.md` § v1.5 carries the rows and the groupings; each WP
file carries its own baseline. Nothing is restated here.

The body has one dominant theme and three smaller ones. The **live-watcher
track** is eighteen rungs, 1401 to 1439, and it answers a question the package
could not answer before: what is my fit doing right now. Beside it sit
**foreign model files** (1118, the largest single WP in the range at 83
commits), **a measured background** (1309), and a set of corrections to what
the package says about itself (1310, 1411, 1412, 1422, 1436, 1437).

1408, 1409 and 1410 closed on 2026-09-14 **before** the tag was cut at 16:13
that day, so they shipped in 1.4.0 and are not here. The ROADMAP's "29 WPs"
counted by date. Five more WPs have a single commit in the range each (1312,
1319, 1338, 1419, 1432); those are mailbox writes by other sessions' handovers
and the WPs remain ⬜.

## Acceptance

**No row here was written at the open, because the open came last.** Protocol
rule 6 asks for Scope and Acceptance at the open, and the [v1.3
record](v1.3.md) already states the reason: a row written after the fact cannot
fail. v1.3's rows were written at ship. These are written after ship, over work
that was reviewed and merged under no milestone at all, which is weaker again.

They are recorded anyway, for the reason v1.3 gives. A milestone with no
statement of what it was for is worse than a milestone whose statement is
retrospective, and every row below names a number a later session can
re-measure. The honest reading of this section is as an inventory. The
evidence that the work is sound is in the twenty-six WP files and the reviews
on their PRs, not here.

**What a later session should take from this**: the milestone was opened late
because nobody opened it early, and four days of parallel sessions produced the
largest unreleased body this repository has held. The fix is procedural and
belongs to whoever opens v1.6.

- **A run is visible while it runs** (1401, 1423–1431). `rietx watch` finds
  every run from `meta.json`, `status.json` and a held `run.lock`, over two
  live layouts, and `runs.project_of` is the one authority on which project a
  run sits in. The page is four files in `watch/static/`, `node --check`ed with
  its DOM-free half under `node --test` at 15 node cases (1430).
- **The live view is numbers a viewer draws** (1402). 180–329 kB a stage
  against the replaced page's 4.51–6.03 MB, and the fit's share 1.03–1.28×
  against 1.04–1.49×. `viz/snapshot.py` imports no plotting library, so a base
  install records one.
- **Recording is default-on, and the bill was measured before it was paid**
  (1403, 1404, 1413, 1438). The recorder costs 1.03–1.28×, which **fails** the
  1.05× gate 1404 set on two cases of three. 84–96 % of it is the per-stage
  snapshot rather than the event stream. Recording stayed on, 1413 cut the
  snapshot by 8.8–11.9× through decimation, and 1438 paid the residue
  deliberately: a ratio is the wrong test where the absolute charge is 50 ms.
- **A human watching a run can stop it** (1405), through the cancel token the
  solver already read, on the unthinned evaluation boundary. `runs.CANCEL_FILE`
  is the whole cross-process seam and an unknown word in it is declined rather
  than obeyed.
- **A poll asks for what the reader can hold** (1427). The console is capped at
  the route; uncapped, a run with 60 000 events built that many `<div>`s to keep
  2000, for 997 ms of frozen main thread. The per-run walk is cached at 1.7× on
  200 runs.
- **Four foreign formats read and written** (1118), refine flags included,
  which all six agents of 1110's round named as the hardest part of the work.
- **A measured background enters as data** (1309), with a refinable scale and
  its own counting statistics folded into σ as σ² + s²·σ_f².
- **The package's own numbers match their sources** (1436, 1437). `help.py`
  printed a Lp formula 0.508× from the one the code computes at 2θ = 90°, and
  `sinθ/λ` is now `s` in equations and `stol` in python. Every refined number
  is bit-identical across the rename.
- **Windows is green, and it is the pre-upload gate** (1439). The nightly went
  red on 2026-09-15, the day after the tag, because the live-watcher track was
  written on POSIX. 0 failed on the reviewed tree, with 5453 tests agreeing
  across platforms.

## Additions this milestone makes, for the release notes

<!-- Staged per protocol rule 6. Entries dated after 2026-09-14 16:13 moved

- **Every fit records itself** (1403, 2026-09-15). `Refinement.fit`,
  `run_stage`, `refine` and `refine_sequential` write a run directory without
  being asked: the event log, a per-stage `snapshot.json`, `summary.txt`,
  `meta.json`, `status.json` and a held `run.lock`. `rietx watch` lists them and
  draws them. 204 kB for a five-stage synthetic LaB6 fit, `[dev]`, macOS arm64.

  *Who has to do something:* anyone fitting on a shared filesystem who does not
  want a parameter trajectory left behind, and anyone whose working directory is
  somebody else's repository. `RIETX_TELEMETRY=0` switches it off for a process,
  `telemetry=False` for a call, `telemetry=<path>` moves the root, and a
  `.gitignore` of `*` goes into the root so runs stay out of `git status`. *Who
  does not:* anyone who wanted the watcher to have something to show, which was
  previously conditional on remembering to pass `events=`.

  *Why it was worth making:* WP-1322 measured three of three subagents switching
  telemetry off, and WP-1401 then measured the cost at 1-3 % of a fit, so the
  knob nobody had to switch on is the one an agent cannot switch off by
  accident. Every configuration returned a bit-identical Rwp: recording does not
  change the answer.

  *What it deliberately is not:* a `capabilities()` flag, because "can this
  build record runs?" always answers yes and the flag would be a literal `True`;
  and a seventh versioned contract, because nothing negotiates over the layout
  yet. `runs.py`'s module docstring holds both refusals, and
  `using/compatibility.md` states the second one to a reader.

  *On Windows*: the recorder was written on POSIX and turned the nightly's
  Windows job red on 2026-09-15, which WP-1439 repaired. No published release
  carried the defect, `runs.py` being new in this one, so nothing here is a fix
  a 1.4.0 user is waiting for. Windows liveness rests on the pid rung alone,
  there being no `run.lock` equivalent until somebody writes one over
  `msvcrt.locking`.

- **The recorder is written so that telemetry cannot break a fit** (1403). Every
  recorder method latches one-shot on `BaseException`, records why in
  `status.json` and warns once a process. A callback you passed through
  `events=` is yours and still runs outside every try block, so a monitoring
  hook that crashes the refinement is still a bug you get to see.

- **`read_gsas_prm` reads a Kα1/Kα2 doublet** (1118, 2026-09-15). A `.prm`
  stating two wavelengths comes back with two emission lines, the second
  weighted by the file's own `KRATIO`. It used to be refused, and the reason
  given was that no file here stated the intensity weight — which was an
  artefact of reading the record by splitting on whitespace, where `KRATIO`
  could not be told from the polarization two fields along. Both are
  conventionally 0.5.

  *Who has to do something:* nobody; a single-wavelength `.prm` reads exactly as
  before, bit for bit on all four real files in `tests/data`. *Who may want to:*
  anyone who read a lab `.prm` and added the Kα2 line by hand afterwards.

  The record is now read by column, through the grammar
  `io/projects/gsas.py` holds and the `.EXP` reader was already using. Two
  readers parsing one record is how they come to disagree about it.

- **A measured background enters as data** (1309, 2026-09-17).
  `BackgroundFixedPlusChebyshev` held a curve and added it with an implicit
  coefficient of exactly 1.0, which is TOPAS's `bkg_file("f.xy")` and only that
  form. It now has the other one, `bkg_file("f.xy", @, s)`: `scale` is a
  refinable multiplier on the curve, `fixed_sigma` carries the curve's own
  counting statistics into the channel weight as σ² + s²·σ_f², `fixed_source`
  records where the curve came from, and `from_pattern` builds all of it from a
  blank `PatternData` so `read_pattern` is the route in. `SCHEMA_VERSION`
  0.20 → 0.21; every new field defaults to the state the member was already in.

  *Who has to do something:* anyone whose plan frees `instrument.background.*`
  over a fixed curve — see the break below. *Who may want to:* anyone who
  scanned an empty can, a blank capillary, a matrix-only specimen or an empty
  furnace, since a blank is never on the specimen's scale and an additive
  polynomial cannot rescale a curve's shape.

  Free the scale against a **low-order** polynomial. Measured on a synthetic
  blank built at 0.85: one Chebyshev term recovers 0.8378(42) and six recover
  0.6479(182), with Rwp falling monotonically across that row. The scale is a
  measurement only where the polynomial cannot describe the curve itself, and
  `HIGH_CORRELATION` against `c0` there is the correct report rather than a
  failure.

- **`rietx watch` is a window into every run, not one directory** (1401,
  1423–1431). At 1.4.0 the verb served a single `LiveSession` directory and
  embedded `fit.html` in a reloading iframe. It now finds every recorded run
  from `meta.json`, `status.json` and a held `run.lock`, ranks them by
  liveness, and draws the pattern, the trajectory and the console in a page
  that keeps the reader's zoom across a stage. `watch.py` was 151 lines and is
  now a package whose four files in `watch/static/` are `node --check`ed, with
  the DOM-free half under `node --test`.

  *Who has to do something:* nobody. *Who may want to:* anyone who was passing
  `events=LiveSession(...)` by hand, which recording now makes unnecessary.

- **A run can be stopped from the page watching it** (1405). `runs.CANCEL_FILE`
  is the whole cross-process seam, and the probe hangs on the cancel token the
  solver already read, at the unthinned evaluation boundary. An unknown word in
  the file is declined into `RunStatus.declined`, so an old recorder meeting a
  newer watcher does not stop a fit it was not asked to stop.
  `RunStatus.cancelled_by` records who asked, because a human's stop and a
  caller's own `token.cancel()` are one cooperative read downstream.

- **A run can be opened in the GUI without touching it** (1428). The watcher's
  GUI verb spawns `rietx gui --scratch` on a byte-for-byte copy, there being no
  read-only way to open a project. `rietx watch --read-only` clears both this
  verb and the stop verb.

- **A caller names its run** (1431). `label=` on every verb that records one,
  so a run list reads as work rather than as identifiers.

- **A refinement is written back out, not only read in** (1118). Nine new
  top-level names: the writers `write_topas_inp`, `write_fullprof_pcr`,
  `write_gsas_exp`, `write_gsas_prm`, `write_gsas2_instprm` and
  `write_gsas2_phase_cif`, and the readers `read_gsas_exp`, `read_gsas2_gpx`
  and `read_gsas2_instprm`. All six agents of 1110's round named
  hand-transcribing a `.inp` as the hardest part of the work.

  *Who has to do something:* nobody; every name is new. The grammar the reader
  still refuses is tracked as WP-1433.

- **One palette and one theme across three browser surfaces** (1429, 1438).
  The GUI, `rietx watch` and `rietx compare` each answered "which colour is the
  calculated curve" for itself, on two different darks. `viz/theme.py` owns the
  values in Python, both Python servers render a `/tokens.css` route, and
  `gui/src/tokens.css` is generated and committed with a test holding it equal
  to the emitter. The theme choice lives in `state_dir/settings.json`, and every
  page that shows it may set it. 1429's writer was the GUI alone, which left the
  choice unreachable for a fit driven from a script and watched in a browser.

- **A degenerate cell is counted, not just survived** (#283, PR #289).
  `StageResult.n_degenerate_cell_probes` and the `CELL_DEGENERATE_PROBE`
  diagnostic report how often a stage reached a non-positive-definite metric.
  The docstrings that claimed "Cell's own bounds keep this rare" are rewritten
  to say what ships: an underdetermined cell stage can reach it often, and the
  guard is what stands between that and silent arithmetic.

- **`help.py`'s Lp entry states the formula the code computes** (1437). It was
  0.508× of it at 2θ = 90° for K = 0.99, with the ratio varying across the
  range, because the help text's `K` was bound to a different quantity from the
  code's. Two more entries were corrected in the same pass.

## Breaks this milestone makes, for the release notes

- **`LiveSession` stops writing `fit.html`** (1402, 2026-09-15). It writes
  `snapshot.json` — the stage's decimated curves, ticks and statistics — and
  `rietx watch` draws them. `runs.SNAPSHOT_FILE` is that file now;
  `runs.LEGACY_SNAPSHOT_FILE` is the old name and `Run.has_legacy_snapshot` the
  flag beside `has_snapshot`.

  *Who has to do something:* anyone whose own code opens
  `<live-dir>/fit.html` after a run, or implements `write_snapshot` on a custom
  `events=` object and expects a page to appear. *Who does not:* anyone
  watching a run, since a `fit.html` already on disk still opens and is still
  served both at `/api/run/<id>/legacy` and by its bare name; and anyone
  calling `rietx html` or `viz.html.write_html`, which are untouched. The
  self-contained emailable page remains a capability; what stopped is producing
  it unasked.

  *Why it was worth making:* the page was built on the fit's own thread, so
  every stage stopped to serialise the whole of plotly afresh — 4.51-6.03 MB
  against the 180-329 kB the numbers take, and 1.04-1.49x a bare fit's wall
  clock against 1.03-1.28x now. It also lost the reader's zoom at every stage,
  precisely when they were looking at something, and it made recording a run
  impossible without plotly installed, because building the figure was how the
  view was stored. `LiveSession` is public, so this is the largest public
  change in the live-watcher track.

- **A project's `live/` holds one directory per run** (1403, 2026-09-15), where
  it held one event log. The path is `live/<run id>/events.jsonl` now.

  *Who has to do something:* anyone whose own code opens
  `<project>.rex/live/events.jsonl` by that path. *Who does not:* anyone opening
  a project, since `project.json`'s schema is untouched and an existing `live/`
  log still resolves as a legacy run that `rietx watch` lists forever; and
  anyone using `Project.live_dir`, which still names the same directory.

  `PROJECT_FORMAT_VERSION` did **not** move, decided deliberately rather than
  overlooked: `live/`'s contents were never part of the format's promise, and
  the schema the version string covers is unchanged.

  *Why it was worth making:* a GUI session and an agent fitting the same project
  interleaved their events into one file, so neither could be read back. One
  directory per run is what separates them, and it is the shape the runs root
  outside a project already had.


- **A fixed background curve no longer covers a range it was not measured
  over** (1309, 2026-09-17). `interpolate_fixed` was bare `np.interp`, which
  clamps to the end values outside the curve's range with no warning: a blank
  measured over 0.5-50° under a specimen scanned to 70° contributed twenty
  degrees of flat invented counts and nothing said so. It now raises, naming
  both ranges and both ways out. The tolerance is one of the curve's own steps,
  because two scans of one nominal range disagree at their ends by about that
  much.

  *Who has to do something:* anyone whose fixed curve stops short of their fit
  range. Crop the fit with `two_theta_min`/`two_theta_max`, or supply a curve
  that covers it. *Who does not:* anyone whose curve came from
  `background.estimate` or `auto_background`, which produce it on the pattern's
  own grid.

- **Every plan preset now frees the fixed curve's scale** (1309, 2026-09-17).
  The presets free `instrument.background.*`, and the scale is a parameter of
  the background, so that glob reaches it. A project with a
  `fixed_plus_chebyshev` background therefore refines one parameter more than it
  did, and its numbers move.

  *Who has to do something:* anyone who wants the curve held exactly where they
  set it — free `instrument.background.c*` instead. *Why it was not made
  opt-in:* the P-spline's `air_scatter` has always been reached by the same
  glob, and a measured background whose scale the shipped plans cannot free
  would need a hand-written plan to do the one thing the feature is for.

- **`constant_wavelength_neutron(fwhm_deg=...)` seeds a different width**
  (#124, 2026-09-15). It seeded `w = (0.5·fwhm)²` **and** `x = fwhm`. `x` is
  the Lorentzian Scherrer term, Γ_L = X/cos θ, so the seed both double-counted
  the width and climbed with angle: at `fwhm_deg=0.3` the seeded TCHZ FWHM was
  0.369° at 2θ = 20 and **1.179° at 150**, which is 3.93× the width asked for,
  worst over exactly the high-angle peaks a neutron cell refinement leans on.
  It now seeds `w = fwhm²` and leaves `x` at its default, holding the seeded
  width within 1.4 % across 20–150°.

  *Who has to do something:* anyone who wants the old starting widths back —
  set `w` and `x` on the profile directly. *Who does not:* anyone reading a
  converged fit, since these terms refine afterwards and every #108 fit
  converged either way. The reason to fix it is that the docstring promises the
  observed width, and the frozen per-stage evaluation windows are sized from it.

  The issue's stated edit and its stated outcome disagreed, and the outcome won.
  Dropping `x` alone, as #124 wrote, leaves Γ_G = √w = fwhm/2, trading a 3.93×
  overshoot for a flat 2× undershoot.

- **`d_spacings` raises where it warned** (#283, PR #289, 2026-09-15). A
  non-positive-definite metric produced a `RuntimeWarning` and a silent NaN. It
  now raises `DegenerateCellError`, naming the cell.

  *Who has to do something:* anyone catching `RuntimeWarning` around a cell that
  can go degenerate. The solver-side guard neutralises such a reach rather than
  failing the stage, so a refinement sees the count and not the exception.

  The same PR proposed physical bounds on `Cell`'s six parameters and that half
  was **withdrawn**: `params/vector.py`'s cell-window machinery and the TOPAS
  reader both read an infinite stored bound as "no claim made", and backfilling
  defaults broke that contract. Where a physical box for the cell belongs is
  still open.
