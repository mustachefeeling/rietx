## Appendix — the AGENT_PROTOCOL literature-grounding audit (WP-1104, 2026-08-18)

[`AGENT_PROTOCOL.md`](../AGENT_PROTOCOL.md) is the operating protocol an LLM
agent reads before refining real data. WP-1068's manual audit found the
failure mode this pass exists to catch: three house rules mis-attributed to
McCusker et al. (1999) during compression (`v1.0.md` § Appendix). The
protocol states the same three rules and had never had the same pass. The
maintainer's instruction: check the protocol is built from experience, not
inference from theory, before amending it.

Method: every normative claim in §§1–10 sorted into three classes — **(i)**
an in-repo measurement that names its WP or record; **(ii)**
literature-grounded, where the paper's own text was read (never its abstract
or a citation chain); **(iii)** a house rule or inference, kept but labeled
as ours. A claim whose named source does not support it is corrected in
place. The maintainer supplied every requested paper.

### Toby (2024) reconciled against §2 and `PLAN_PRESETS`/`PLAN_INFO`

The paper's thesis: no fixed parameter order is correct, because the right
next parameter depends on the data and the current values — so GSAS-II
computes the "worst-fit parameter" (largest |∂χ²/∂p| with same-sign one-sided
derivatives at p ± δ) instead of following a recipe. Read against this
package, difference by difference:

1. **Static presets vs a computed next parameter — already both, adopt by
   cross-citation.** The presets encode the staged discipline;
   `Refinement.suggest()` / `task="suggest"` (WP-1050) is the state-dependent
   answer Toby's mechanism computes — a Gauss-Newton one-parameter gain off
   one analytic Jacobian build, ranking every held parameter by predicted
   Δχ². The gain is Toby's |∂χ²/∂p| with the curvature already divided out,
   so a stiff parameter with a large gradient and nothing to give ranks low
   rather than first. §2 now points at §9c for this.
2. **The two-sided δ test — declined, with the reason on record.** Toby
   brackets the minimum with χ²(p ± δ) to tell real leverage from roundoff,
   because GSAS-II's probe differentiates numerically. This package's
   gradient is analytic (JᵀR), so a converged parameter's one-parameter gain
   is zero by construction rather than by test; the filter answers a
   finite-difference problem the machinery here does not have.
3. **Cell before scale when the cell is off — declined, two reasons.** Toby:
   with partial peak overlap but a far-from-optimal cell, the cell must be
   optimised before the scale can be. Here the stages are *cumulative*, so
   the `cell` stage re-optimises the scale jointly and a mediocre stage-1
   scale costs iterations, never the answer; and past the ~1 % precondition
   the frozen evaluation windows mean **no** order walks the cell in — the
   package's answer to a far cell is `MODEL_FAR_FROM_DATA` and re-indexing
   (§1, §7d), not a different recipe. No preset changed (this WP's non-goal;
   nothing measured here says one should be).
4. **Weighted difference plots — already the invariant, adopt by citation.**
   Toby gives three reasons the Δ/σ difference beats the raw one. Every
   difference curve this package draws has been Δ/σ since WP-1029
   (`result.sig()`, one authority); §5 now cites the paper for it.
5. **"Not all of these parameters are appropriate to vary" — already
   structural.** Toby's own caveat on his mechanism (his Fig. 2c: an
   instrumental broadening term out-derivatives the sample term that should
   move). WP-1050's handover records the identical example — the leverage
   ranking *will* rank U/V/W while Layer 2 structurally cannot suggest it —
   and the strategy veto, `mode_fixed` and `lab_sample_refine`'s frozen
   instrument are where the protocol encodes the caveat.

**Open, recorded:** whether a dynamic worst-fit *loop* (suggest → free → fit
→ repeat) beats the presets on the planted-cause fixtures is a measurable
question no session has measured. The eval harness (WP-1052/1053, next round

Corroborations with no change needed: the staged-release rationale (§2 —
"parameters may refine to unrealistic values. At this point it becomes
unlikely that including additional parameters … will allow the model to

largest-derivative groups rather than tradition; and the design premise
itself — the paper closes by envisioning software that judges
parameterisation, plausibility and model expansion, which is the FitReport's
