# rietx 1.0.0

First public release. rietx is an API-first Rietveld refinement package for
powder XRD: `pip install rietx`, then start at the
[manual](../manual/index.md). The stability promise — what is frozen, what
is provisional, how changes are classified — is the manual's
[Compatibility](../manual/using/compatibility.md) chapter; this page lists
what changed on the way to 1.0 and what 1.0.x will bring.

For anyone moving from a pre-release checkout, the changes that can move a
number you quote come first.

## Numbers that move

- **Anomalous dispersion is on by default.** Scattering factors are now
  f₀ + f′ + i·f″, with f′/f″ from the bundled Cromer–Liberman tables by
  species and wavelength, and structure factors returned as the Friedel
  average. The exact escape hatch: `Source.dispersion = None` declines the
  correction, reproduces every pre-1.0 number bit-identically, and says so
  with a `DISPERSION_NEGLECTED` diagnostic. Near an absorption edge the
  bundled table is wrong in principle, not merely coarse, so it is refused
  rather than smeared — an emission line whose f′/f″ differ from the primary
  line's by more than 1 % of Z raises — and `Dispersion.overrides` takes
  measured pairs instead.
- **Plot defaults changed** on `RefinementResult.plot` and its renderers:
  `two_theta_range` is a window on the pattern (points outside it are not
  drawn or scaled against), the difference panel draws Δ by default
  (`weighted=True` restores Δ/σ with its ±3σ band), and `dpi` defaults
  to 300.
- **`report_trajectory` defaults to false** on the agent surface. Measured
  on the agent evals: unasked per-stage rungs bought no better decisions at
  more calls. The trajectory is still there — `report_trajectory: true` in a
  `refine` request, or `fit(stage_reports=True)` in the library — and the
  fit's answer is bit-identical either way.

## Status at 1.0

- **The GUI ships as beta**, its HTTP routes included. The JSON dialect
  (non-finite floats as the strings `"Infinity"`/`"-Infinity"`/`"NaN"`) and
  the raw-bytes upload routes are stated normatively in the Compatibility
  chapter; everything else about the wire may change in 1.0.x.
- **The `.rxt` text document is provisional.** It is rendered in-session and
  never persisted, so nothing accumulates in it.
- **A series is session-scoped.** `refine_sequential` writes one history
  tree per pattern, but the series itself — the trajectories, the pass
  structure — is not a saved document. Persisting it is fenced to post-1.0
  work together with the multi-histogram project seam.
- **The undocumented half of the Python surface is provisional.** The manual
  documents the floor; each 1.0.x chapter that lands freezes the names it
  documents. The Compatibility chapter has the three-bucket rule.

## Promised in 1.0.x

- **`.rex` project transport as a zip**: an export-as-zip / open-zip pair,
  defined as the project directory, zipped — transport, not a second format.
  Until then a `.rex` directory travels as whatever archive you make of it,
  and the stored fingerprints detect a cloud-sync-torn copy on open.

## Notes for integrators

- **`PlanSpec.stages` accepts an empty list.** The schema is shared with
  history headers, which are written before the first stage runs, so the
  schema cannot require a stage. The check lives at the request surface: a
  `refine` request naming an unknown or empty plan is refused there. Do not
  rely on schema validation alone to catch a plan with no stages.
- **Deliver the report's sentences to your model, not only its numbers.**
  Measured on the agent evals: the report's follow-through sentence (what a
  decisive rival swap licenses) was delivered in every response, but reached
  the calling model's context in 2 of 12 cells — the agents piped output to
  files and grepped statistics back, and the sentence is what the greps
  dropped. Where that text should land so a caller actually reads it is an
  open question of placement, not wording; until it settles, make sure your
  caller reads `FitReport.summary` verbatim.
