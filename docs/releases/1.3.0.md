# rietx 1.3.0

**The agents-and-programs milestone**, in flight. This file is opened by the
first work package with a consumer-visible break to record and accumulates
until the milestone ships; the milestone record
([`docs/milestones/v1.3.md`](../milestones/v1.3.md)) carries the narrative and
the measurements meanwhile.

## Install

```sh
pip install --upgrade rietx
```

## The JSON envelope is gone

`rietx.agent` — `refine_json`, the five request types, the `{ok, error}`
response envelope, `tool_definition`, `request_schema` and `response_schema` —
is deleted. So is its manual chapter's envelope half; what remains under
[Calling rietx from a program](https://rietx.org/using/agents.html) is the
Python API and `capabilities()`.

It is deleted rather than deprecated because it was measured and not used.
Four traced rounds — 235 instrumented interpreter starts in the surface round,
a 91-call ramp run, a contributor's four projected runs and the same
contributor's 5 430-call bundle — recorded **zero** calls of it from any agent
that had a choice. Every one of them drove the package directly. It also could
not serve the case it was built for: requests carried patterns inline, so one
lab pattern is about 11 k tokens and a 68-pattern series is about 754 k in a
single call.

Nothing that computes changed. `RefinementResult`, `FitReport`, `SeriesResult`,
`IndexingResult` and `SuggestionResult` are untouched and serialize byte for
byte, so a stored answer from 1.2 still validates.

## The protocol is a skill

`docs/AGENT_PROTOCOL.md` is now an **Agent Skill**: a directory
(`docs/skill/rietx/`) holding a `SKILL.md` an agent reads whole and reference
files it loads only when a task calls for one. The format is
[an open standard](https://agentskills.io/specification), read natively by
Claude Code, Codex, Cursor, Copilot, Gemini CLI, opencode, Goose, Cline, Amp,
Kiro, Devin, Zed, Junie, Qwen Code and OpenHands among others; nothing in the
frontmatter is specific to one of them.

**No rule was removed and no section renumbered.** What moved is where a
lookup sits: the diagnostics table, the abstention table, the twenty surprises,
the indexing chapters, the history and series chapters, the measured evidence
behind §4's rules and the API index are now files beside the body rather than
inside it, and the body's index table says when to open each. The API index is
**generated** from the installed package — every signature, constructor field
and default rendered by `docs/skill/make_api_index.py`, none typed — and a test
fails when the committed file is older than the code.

The reason is a measurement. The single file had reached 144 427 B — 2.2× what
an agent's Read tool returns in one call — so an agent that tried to load it got
lines 1-707 and then went hunting with `grep` and `sed`, five roundtrips for one
document, with the 99-row diagnostics table never reaching context at all.

- **You read the file at `docs/AGENT_PROTOCOL.md` or
  `https://rietx.org/AGENT_PROTOCOL.md`.** Both still resolve, to a pointer.
  The skill is at `docs/skill/rietx/SKILL.md` and
  `https://rietx.org/skill/rietx/SKILL.md`. **The pointer is deleted in v1.4.**

- **You read the wheel's copy at `rietx/data/AGENT_PROTOCOL.md`.** That path
  now holds the same pointer, for one release; the skill is at
  `rietx/data/skill/rietx/`. Do not build either path: `capabilities().skill_path`
  and `rietx skill --path` answer with wherever this build keeps it, including a
  source checkout. **The pointer's wheel path goes in v1.4 with the file.**

- **You want it in your own repository.** `rietx skill --install` writes one
  copy to `.agents/skills/rietx/` and links every harness that reads elsewhere;
  `--agent NAME` chooses, `--list-agents` prints the table with each row's
  source and date, `--user` targets your home directory and `--copy` copies
  instead of linking. It prints, and never writes, the two lines naming the
  skill in your `AGENTS.md` or `CLAUDE.md`.

- **Your harness reads no skills.** `rietx skill --print` gives the body as
  plain text and `--print all` the whole tree, for a `--read` flag or a system
  prompt.

There is deliberately no `rietx[claude]`-style extra: a pip extra can only add
a dependency, never write a file into your project, which is the whole of what
installing a skill means.

## `suggest` now says whether the parameter pays for itself

`Refinement.suggest` ranked held parameters by leverage — the predicted Δχ²
from freeing one. Leverage is not the decision: at powder-pattern channel
counts an improvement can be real, ranked first, and still not worth the
parameter it costs. So every `CandidateGroup` now carries `delta_bic`,
Schwarz's ΔBIC at the Gauss-Newton prediction of what freeing the group
reaches, in the sign the rest of the package uses (**positive favours
freeing**) and through the one form it uses (`report.layer2.delta_bic`).

`Refinement.summary()`'s `next:` line is that number rather than the standing
instruction to go and run `suggest` — `next: free instrument.profile.w,
predicted ΔBIC +48.2 (Δχ² 1.2e+03)`, or `next: nothing ΔBIC admits` when the
leading candidate does not clear it.

The traced ramp run is why: its agent ran two extra refinements per candidate
to compute exactly this, held zero shift and sample displacement on the answer,
and called `suggest` five times without it answering the question it had.

## Upgrading

Who has to do something, and what.

- **You called `rietx.agent.refine_json`.** Call the package directly and dump
  the answer:

  ```python
  ref = rx.Refinement(structure, instrument)
  result = ref.fit(data, plan="mccusker_default")   # or rx.refine(...)
  answer = result.model_dump(mode="json")           # the old `result` arm
  ```

  The report is `ref.report()` (the old `report` arm) and the per-stage rungs
  are `ref.stage_reports_` after `fit(stage_reports=True)` (the old
  `trajectory`). `task="refine_multi"` is `rx.refine_multi`,
  `task="refine_sequential"` is `rx.refine_sequential`, `task="index"` is
  `rx.index_pattern`, and `task="suggest"` is `Refinement.suggest`.

  **Failures raise where the envelope returned `ok: false`.** Catch
  `ValueError` for what returned `INVALID_REQUEST`, `NoPhasesError` for
  `NO_PHASES` — a `ValueError` subclass, so catch it *first* if you branch on
  both — and `RuntimeError` for `REFINEMENT_FAILED`. There is no
  `BACKEND_UNAVAILABLE` equivalent to catch: ask `capabilities().backends`
  before choosing one, which is where that answer always came from.

- **You registered `tool_definition()` in a tool loop.** No traced run ever
  did, so this is written for completeness. Wrap the Python API in your own
  tool and give it **path** arguments — a pattern file, a CIF, a project
  directory — rather than inline payloads; the arrays are what made the inline
  form expensive.

- **You read `capabilities().features`.** `agent_json` is gone from the map.
  `report_trajectory` stays and now reports whether `Refinement.fit` accepts
  `stage_reports`.

- **You pin `capabilities().schema_version`.** It moves 0.11 → 0.14, in three
  steps: 0.12 removes the envelope's models (every earlier step on that ladder
  added something), 0.13 adds `Capabilities.skill_path`, and 0.14 adds
  `CandidateGroup.delta_bic`. The comment beside the constant carries all
  three.

- **You store or parse a `SuggestionResult`.** Its groups carry `delta_bic`,
  and it is **required**: a stored 1.2 suggestion does not validate against
  1.3, because a default of 0.0 on a model-selection field would read as "this
  parameter is exactly worth its cost" — an answer nobody computed. Re-run
  `Refinement.suggest`; it is one Jacobian build and no solve. Every other
  answer type still validates unchanged.

- **You imported anything else from `rietx.agent`.** `rietx.agent` now raises
  an `AttributeError` that names the replacement rather than a bare "no
  attribute".
