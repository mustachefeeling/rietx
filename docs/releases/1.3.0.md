# rietx 1.3.0

**The agents-and-programs milestone.** The surface a program drives this
package through, refactored against two measured runs rather than intuition: a
result that says whether it is done, a phase the data cannot see held rather
than bounded, the operating protocol as an Agent Skill, one integration surface
instead of two, and the PowderLine recipe as an interchange format.

**The forward model is untouched** — no correction, profile or structure-factor
term moved, so a fit whose phases are all supported by the data gives what 1.2.0
gave. One change reaches an ordinary refinement anyway, and it is the first
section below: a phase the data cannot see now has its structural parameters
held for the stage, which means they are **absent** from
`RefinementResult.parameters` rather than reported at whatever the solver
walked them to.

## Install

```sh
pip install --upgrade rietx
```

## A phase the data cannot see is held, not bounded

A phase reaches the pattern only through `scale × |F|² × profile`, so at a
floored scale nothing of it moves Rwp while its cell wanders out of the
physical range. A stage now **holds** every free structural parameter of such a
phase for the duration, leaving its `scale` free — the one direction that is
not flat, so the phase can still appear — and records what it did in
`StageResult.held` and `StageResult.released`.

Support is a fact about the values and a stage moves them, so it is re-measured
at the answer: a phase that appeared is released and the stage re-solved, one
that collapsed while solving is put back where the stage found it and held. One
extra solve covers either case, never a third.

**A held parameter is absent from `RefinementResult.parameters`.** That is the visible
change, and it is deliberate — a value that is not a measurement is the
caller's to supply, not this package's to report. A trajectory of a phase that
appears part-way through a series now starts at the onset instead of opening
with cells nobody measured. `PHASE_UNCONSTRAINED` says what was done rather
than only that something was wrong.

Measured on an in-situ ramp's 13 sub-onset patterns, through the call an agent
actually made: 2164 iterations and a cell 14.9 Å from truth with the parameter
free, 1342 and 0.163 Å with the bounds that agent added by hand, and 1669 with
no cell reported at all here.

## A result tells you whether it is done

`print(result)` used to give you a repr. `RefinementResult.__str__`,
`Refinement.summary(deliverable=, plot=)` and `SeriesResult.summary()` now
answer "done or not, and why" in one call: the numerical heuristics first, and
the visual check named rather than substituted for.

```python
result = ref.fit(data, plan="mccusker_default")
print(result)                          # status, statistics, and what to look at next
ref.summary(deliverable="qpa")         # the same, for the deliverable you actually have
```

`deliverable="series"` is answered by **`SeriesResult.summary()`**, not by
`Refinement.summary()` — a caller of `refine_sequential` holds no `Refinement`,
and no single pattern carries a `SEQUENTIAL_*` row. It names
`SEQUENTIAL_PATH_DEPENDENT`, `SEQUENTIAL_PERSISTENT_FINDING`,
`SEQUENTIAL_DISCONTINUITY` and `PHASE_UNCONSTRAINED` as stopping criteria
rather than as messages, and `refine_sequential(..., verify_discontinuities=True)`
refits a flagged step's two patterns cold and independently, writing the cold
step over the chain's. On a 68-pattern chain that check costs **+5 %** and every
flagged step reproduced at 1.00.

Three smaller changes ride with it, all measured on the same campaign:

- **A wrong name answers with the right one.** `Base.__getattr__` across all
  134 schema subclasses, `Stage` and `RefinementPlan`'s own version, and a
  derived top-level re-export of every public schema class — so `rx.Source`,
  `rx.EmissionLine` and `rx.BackgroundChebyshev`, named throughout the manual,
  are importable rather than merely documented.
- **`HIGH_CORRELATION` deduplicates across a plan's stages and caps at 10 per
  fit.** A fit whose diagnostics ran to 35.2 kB — enough that one harness
  truncated it to a 2 kB preview and read nothing — is 3.5 kB from this alone.
- **`progress=` on `fit` and `refine_sequential`** writes one line per stage
  boundary. It is an `events=` subscriber, never a second channel.

## The JSON envelope is gone

`rietx.agent` — `refine_json`, the five request types, the `{ok, error}`
response envelope, `tool_definition`, `request_schema` and `response_schema` —
is deleted. So is its manual chapter's envelope half; what remains under
[Calling rietx from a program](https://rietx.org/using/agents.html) is the
Python API and `capabilities()`.

It is deleted rather than deprecated because it was measured and not used.
Four traced rounds — 235 instrumented interpreter starts in the surface round,
a 91-call ramp run, a contributor's four projected runs and the same
contributor's 5 430-call bundle — recorded **zero** calls of it from any agent
that had a choice. Every one of them drove the package directly. It also could
not serve the case it was built for: requests carried patterns inline, so one
lab pattern is about 11 k tokens and a 68-pattern series is about 754 k in a
single call.

Nothing that computes changed. `RefinementResult`, `FitReport`, `SeriesResult`,
`IndexingResult` and `SuggestionResult` are untouched and serialize byte for
byte, so a stored answer from 1.2 still validates.

## The protocol is a skill

`docs/AGENT_PROTOCOL.md` is now an **Agent Skill**: a directory
(`docs/skill/rietx/`) holding a `SKILL.md` an agent reads whole and reference
files it loads only when a task calls for one. The format is
[an open standard](https://agentskills.io/specification), read natively by
Claude Code, Codex, Cursor, Copilot, Gemini CLI, opencode, Goose, Cline, Amp,
Kiro, Devin, Zed, Junie, Qwen Code and OpenHands among others; nothing in the
frontmatter is specific to one of them.

**No rule was removed and no section renumbered.** What moved is where a
lookup sits: the diagnostics table, the abstention table, the twenty surprises,
the indexing chapters, the history and series chapters, the measured evidence
behind §4's rules and the API index are now files beside the body rather than
inside it, and the body's index table says when to open each. The API index is
**generated** from the installed package — every signature, constructor field
and default rendered by `docs/skill/make_api_index.py`, none typed — and a test
fails when the committed file is older than the code.

The reason is a measurement. The single file had reached 144 427 B — 2.2× what
an agent's Read tool returns in one call — so an agent that tried to load it got
lines 1-707 and then went hunting with `grep` and `sed`, five roundtrips for one
document, with the 99-row diagnostics table never reaching context at all.

- **You read the file at `docs/AGENT_PROTOCOL.md` or
  `https://rietx.org/AGENT_PROTOCOL.md`.** Both still resolve, to a pointer.
  The skill is at `docs/skill/rietx/SKILL.md` and
  `https://rietx.org/skill/rietx/SKILL.md`. **The pointer is deleted in v1.4.**

- **You read the wheel's copy at `rietx/data/AGENT_PROTOCOL.md`.** That path
  now holds the same pointer, for one release; the skill is at
  `rietx/data/skill/rietx/`. Do not build either path: `capabilities().skill_path`
  and `rietx skill --path` answer with wherever this build keeps it, including a
  source checkout. **The pointer's wheel path goes in v1.4 with the file.**

- **You want it in your own repository.** `rietx skill --install` writes one
  copy to `.agents/skills/rietx/` and links every harness that reads elsewhere;
  `--agent NAME` chooses, `--list-agents` prints the table with each row's
  source and date, `--user` targets your home directory and `--copy` copies
  instead of linking. It prints, and never writes, the two lines naming the
  skill in your `AGENTS.md` or `CLAUDE.md`.

- **Your harness reads no skills.** `rietx skill --print` gives the body as
  plain text and `--print all` the whole tree, for a `--read` flag or a system
  prompt.

There is deliberately no `rietx[claude]`-style extra: a pip extra can only add
a dependency, never write a file into your project, which is the whole of what
installing a skill means.

## `suggest` now says whether the parameter pays for itself

`Refinement.suggest` ranked held parameters by leverage — the predicted Δχ²
from freeing one. Leverage is not the decision: at powder-pattern channel
counts an improvement can be real, ranked first, and still not worth the
parameter it costs. So every `CandidateGroup` now carries `delta_bic`,
Schwarz's ΔBIC at the Gauss-Newton prediction of what freeing the group
reaches, in the sign the rest of the package uses (**positive favours
freeing**) and through the one form it uses (`report.layer2.delta_bic`).

`Refinement.summary()`'s `next:` line is that number rather than the standing
instruction to go and run `suggest` — `next: free instrument.profile.w,
predicted ΔBIC +48.2 (Δχ² 1.2e+03)`, or `next: nothing ΔBIC admits` when the
leading candidate does not clear it.

The traced ramp run is why: its agent ran two extra refinements per candidate
to compute exactly this, held zero shift and sample displacement on the answer,
and called `suggest` five times without it answering the question it had.

## rietx speaks the PowderLine recipe

`rx.read_recipe(path)` reads a
[PowderLine](https://github.com/NSLS2/PowderLine) `GSASII_Rietveld` JSON recipe
into a structure, an instrument, a pattern, a plan and its `fit_range`;
`rx.write_recipe_tables` writes a finished refinement back out as the four
tables its consumers read. That makes this package one of the engines such a
pipeline can dispatch to. Nothing existing changes — it is a reader and a
writer, and `capabilities().features["powderline_recipe"]` is how a client
asks whether a build has them.

Every unit conversion was measured against the reference output PowderLine
commits beside its own recipes rather than adopted from its prose, and the one
row the format states two ways — `Zero`, centidegrees in one of its modules and
degrees in another — is **refused** rather than picked. The full table, the
refusals and the diagnostics are `docs/manual/using/recipe.md`.

The fixtures turned out to be worth more than the format. Each is one pattern
refined by **two** independent engines with both outputs committed, and on the
two-phase cathode the two references disagree by 2665 ppm on the cubic cell —
GSAS-II reports its own fit singular there and returns a negative crystallite
size. This package lands 11–93 ppm from TOPAS on all five free cell parameters,
at Rwp 7.333 % against TOPAS's 7.326 %. Read it as the calibration for any
cross-code claim: across engines the cells are comparable and the broadening
coefficients are not.

## Contract versions

Six versioned contracts, and `capabilities()` is where a program reads them
rather than this table. One moved since 1.2.0:

| Contract | 1.2.0 | 1.3.0 |
|---|---|---|
| `schema_version` | 0.10 | **0.14** |
| `report_thresholds_version` | 1.4 | 1.4 |
| `project_format_version` | 1.3 | 1.3 |
| `indexing_thresholds_version` | 1.3 | 1.3 |
| `event_schema_version` | 2 | 2 |
| `textdoc_format_version` | 1 | 1 |

`schema_version` moved four times; the Upgrading note below is the summary and
the comments beside the constant are the authority. Two of the four can refuse
a document you already have. A stored 1.2 `SuggestionResult` does not validate
against 1.3, because `delta_bic` is required rather than defaulted — the reason
is in Upgrading. And the envelope's own models are gone, so a stored
`{ok, error}` request or response no longer has a type here to validate against;
the five **answer** types it wrapped are untouched and load unchanged.

## Upgrading

Who has to do something, and what.

- **You called `rietx.agent.refine_json`.** Call the package directly and dump
  the answer:

  ```python
  ref = rx.Refinement(structure, instrument)
  result = ref.fit(data, plan="mccusker_default")   # or rx.refine(...)
  answer = result.model_dump(mode="json")           # the old `result` arm
  ```

  The report is `ref.report()` (the old `report` arm) and the per-stage rungs
  are `ref.stage_reports_` after `fit(stage_reports=True)` (the old
  `trajectory`). `task="refine_multi"` is `rx.refine_multi`,
  `task="refine_sequential"` is `rx.refine_sequential`, `task="index"` is
  `rx.index_pattern`, and `task="suggest"` is `Refinement.suggest`.

  **Failures raise where the envelope returned `ok: false`.** Catch
  `ValueError` for what returned `INVALID_REQUEST`, `NoPhasesError` for
  `NO_PHASES` — a `ValueError` subclass, so catch it *first* if you branch on
  both — and `RuntimeError` for `REFINEMENT_FAILED`. There is no
  `BACKEND_UNAVAILABLE` equivalent to catch: ask `capabilities().backends`
  before choosing one, which is where that answer always came from.

- **You registered `tool_definition()` in a tool loop.** No traced run ever
  did, so this is written for completeness. Wrap the Python API in your own
  tool and give it **path** arguments — a pattern file, a CIF, a project
  directory — rather than inline payloads; the arrays are what made the inline
  form expensive.

- **You read `capabilities().features`.** `agent_json` is gone from the map and
  `powderline_recipe` is new in it. `report_trajectory` stays and now reports
  whether `Refinement.fit` accepts `stage_reports`.

- **You pin `capabilities().schema_version`.** It moves 0.10 → 0.14, in four
  steps: 0.11 adds `StageResult.held` and `StageResult.released`, 0.12 removes
  the envelope's models (every earlier step on that ladder added something),
  0.13 adds `Capabilities.skill_path`, and 0.14 adds `CandidateGroup.delta_bic`.
  The comment beside the constant in `schemas/common.py` carries all four, with
  the reason each moved the string.

- **You store or parse a `SuggestionResult`.** Its groups carry `delta_bic`,
  and it is **required**: a stored 1.2 suggestion does not validate against
  1.3, because a default of 0.0 on a model-selection field would read as "this
  parameter is exactly worth its cost" — an answer nobody computed. Re-run
  `Refinement.suggest`; it is one Jacobian build and no solve. Every other
  answer type still validates unchanged.

- **You imported anything else from `rietx.agent`.** `rietx.agent` now raises
  an `AttributeError` that names the replacement rather than a bare "no
  attribute".

- **You read `RefinementResult.parameters` for a phase that may be absent.**
  A parameter held for want of support is **not in that mapping**, where before
  it carried whatever the solver had walked it to. Code that indexed it
  unconditionally now needs a `.get`, and `StageResult.held` is where the stage
  says which paths and why. This is the change most likely to reach a series
  script, and it is the one that makes a trajectory start where the phase does.

- **You run `rietx` from a Windows pipe.** `rietx skill --print` and
  `rietx index --help` exited 1 with a `UnicodeEncodeError` when stdout was
  captured rather than a console, because the ANSI code page has no `α` or `Å`.
  The CLI now pins its own output to UTF-8 on every platform.
