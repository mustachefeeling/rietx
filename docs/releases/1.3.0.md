# rietx 1.3.0

**The agents-and-programs milestone**, in flight. This file is opened by the
first work package with a consumer-visible break to record and accumulates
until the milestone ships; the milestone record
([`docs/milestones/v1.3.md`](../milestones/v1.3.md)) carries the narrative and
the measurements meanwhile.

## Install

```sh
pip install --upgrade rietx
```

## The JSON envelope is gone

`rietx.agent` — `refine_json`, the five request types, the `{ok, error}`
response envelope, `tool_definition`, `request_schema` and `response_schema` —
is deleted. So is its manual chapter's envelope half; what remains under
[Calling rietx from a program](https://rietx.org/using/agents.html) is the
Python API and `capabilities()`.

It is deleted rather than deprecated because it was measured and not used.
Four traced rounds — 235 instrumented interpreter starts in the surface round,
a 91-call ramp run, a contributor's four projected runs and the same
contributor's 5 430-call bundle — recorded **zero** calls of it from any agent
that had a choice. Every one of them drove the package directly. It also could
not serve the case it was built for: requests carried patterns inline, so one
lab pattern is about 11 k tokens and a 68-pattern series is about 754 k in a
single call.

Nothing that computes changed. `RefinementResult`, `FitReport`, `SeriesResult`,
`IndexingResult` and `SuggestionResult` are untouched and serialize byte for
byte, so a stored answer from 1.2 still validates.

## Upgrading

Who has to do something, and what.

- **You called `rietx.agent.refine_json`.** Call the package directly and dump
  the answer:

  ```python
  ref = rx.Refinement(structure, instrument)
  result = ref.fit(data, plan="mccusker_default")   # or rx.refine(...)
  answer = result.model_dump(mode="json")           # the old `result` arm
  ```

  The report is `ref.report()` (the old `report` arm) and the per-stage rungs
  are `ref.stage_reports_` after `fit(stage_reports=True)` (the old
  `trajectory`). `task="refine_multi"` is `rx.refine_multi`,
  `task="refine_sequential"` is `rx.refine_sequential`, `task="index"` is
  `rx.index_pattern`, and `task="suggest"` is `Refinement.suggest`.

  **Failures raise where the envelope returned `ok: false`.** Catch
  `ValueError` for what returned `INVALID_REQUEST`, `NoPhasesError` for
  `NO_PHASES` — a `ValueError` subclass, so catch it *first* if you branch on
  both — and `RuntimeError` for `REFINEMENT_FAILED`. There is no
  `BACKEND_UNAVAILABLE` equivalent to catch: ask `capabilities().backends`
  before choosing one, which is where that answer always came from.

- **You registered `tool_definition()` in a tool loop.** No traced run ever
  did, so this is written for completeness. Wrap the Python API in your own
  tool and give it **path** arguments — a pattern file, a CIF, a project
  directory — rather than inline payloads; the arrays are what made the inline
  form expensive.

- **You read `capabilities().features`.** `agent_json` is gone from the map.
  `report_trajectory` stays and now reports whether `Refinement.fit` accepts
  `stage_reports`.

- **You pin `capabilities().schema_version`.** It moves 0.11 → 0.12. Every
  earlier step on that ladder added something; this one removes the envelope's
  models, and the comment beside the constant says so.

- **You imported anything else from `rietx.agent`.** `rietx.agent` now raises
  an `AttributeError` that names the replacement rather than a bare "no
  attribute".
