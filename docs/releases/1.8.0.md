# rietx 1.8.0

This release carries everything that reached `main` in the four days after 1.7.0, 46 merged pull requests.
Four changes are the largest.
Every parameter is now refined in its own units, and the default driver is LM, so every converged fit can move.
The compiled kernels are a Rust wheel, `rietx-kernels`, where they were numba.
An install is 139 MB smaller, and an Intel Mac can install rietx again.
A CIF rietx writes now states what IUCr checkCIF computes, and a refinement CIF holds every measured point.
And a rigid body can carry torsions about named bonds, with a check that asks whether the data want the body a different shape.

On the 11-BM NAC example every figure README quotes is unchanged.
17 of the 129 rows of [VALIDATION.md](https://github.com/yue-here/rietx/blob/main/docs/VALIDATION.md) moved by more than 1 %, and it quotes the figures the 1.8.0 tree gives.
On NIST SRM 660c LaB₆, for one, the cell reads 25 ppm above the certificate, where 1.7.0 read 28 ppm.
A Pawley fit with more than 128 columns can stop a stage on its evaluation cap under the new driver, and `solver="trf"` avoids it (see [Numbers that move](#numbers-that-move)).
Everything that changes what 1.7.0 code gets back is in [Upgrading](#upgrading).

## Install

```sh
pip install --upgrade rietx
```

rietx now installs `rietx-kernels` in place of numba.
It has wheels for Linux, macOS and Windows on Python 3.11 or later, and no source distribution, so the platforms it covers are listed [below](#the-compiled-kernels-are-a-wheel).

## Upgrading

### Code to check

Code written against 1.7.0 runs unaltered, with the exceptions in this list.

- `Parameter.transform` is gone (WP-1938).
  Passing `transform=` to `Parameter` still works and becomes bounds, but reading `.transform` raises `AttributeError`.
  `ParameterRow.transform` is gone too.
- `Refinement.add_variable` and `ParameterTable.add_parameter` no longer take `transform=`.
  Pass the bounds instead, for example `min=0.0`.
- `strategy.suggest.Candidate.dp_du` is gone, since every column is in physical units.
- A parameter that refines onto a lower bound of 0 reports `FLOOR_HIT`, where it reported `BOUND_HIT` (WP-1929).
  That covers a scale, a width, a B with `min=0`, and W on its floor.
  Code that finds rows on a bound by `code == "BOUND_HIT"` should read both codes, or `RefinedParameter.at_bound`, which is `True` under either.
- An event log opened by `EventStream` now starts with a header line, `{"record": "run", …}` ([#902](https://github.com/yue-here/rietx/pull/902) by @mustachefeeling, issue #223).
  The line goes to the file only, so no callback sees it, and `read_events` skips it.
  A reader of your own that validates each line as an `EventRecord`, or reads `e["kind"]`, needs to skip it too.
  `EVENT_SCHEMA_VERSION` is `3`, where it was `2`.
- The module `rietx.params.transforms` is gone, and `logaddexp` and `sigmoid` left the backend op list.
  A custom backend no longer needs to provide them.
- The isotropy `Witness` stores one more field, `interior`, so a `Witness` built by hand needs it.
- `capabilities().schema_version` is `0.49`, where 1.7.0's was `0.43`.
  0.44 adds `StageResult.seeded`, 0.45 adds `RigidBody.torsions`, and 0.46 removes `Parameter.transform`.
  0.47 adds `BackgroundSelection.diagnostics`, 0.48 adds `ParameterInterval`, and 0.49 adds `StageResult.moment_angle_tests`.
  Every document 1.7.0 wrote opens unchanged.
  1.7.0 refuses a result this release writes, and a structure that carries a rigid body, even one with no torsions.

### Numbers that move

- Every parameter is refined in its own units, and the default driver is LM, where it was TRF (WP-1938).
  A width or a scale used to be refined through a softplus, a map that kept it above zero.
  Near zero that map left the last digits of a fit to rounding, so two machines could reach different minima, and an esd depended on where the solver stopped.
  Now a parameter's `min` and `max` are bounds the driver holds directly.
  TRF crawls on such bounds, so LM became the default.
  On SRM 660c and NAC, LM is 1.19–1.30× faster than TRF.
  On corundum and on a four-phase QPA pattern, TRF stops on its iteration limit and LM converges.
  Every converged fit can move.
  On the 11-BM LaB₆ + cBN Le Bail pattern from cells 0.36 % long, pass 1 reads Rwp 13.918 %, where TRF read 13.847 %.
  `solver="trf"` stays selectable.
  It can now stall on a positive parameter started far from its answer: a PbSO₄ scale started 2400 times too high ends at χ² 4.5e5 under TRF, with Pb Biso 133 Å², and at 7111 under LM (issue #900).
- The LM driver solves each step exactly inside the parameter bounds (WP-1937), so a parameter that ends on a bound sits on it.
  Its budget is `max_iter × 4` residual evaluations, as TRF's is, where it was `max_iter` outer iterations.
  A stage that starts at its minimum reports `converged`.
  It said `diverged`, and a series set such a pattern aside.
- A Pawley fit with more than 128 columns can stop a stage on its evaluation cap under LM.
  Above 128 columns each step is an approximate one, because the exact solve took 0.8 s to 177 s per step there.
  On the GSAS-II fluorapatite tutorial pattern, 343 columns, the `profile` stage stops at its cap at Rwp 8.036 %, where 1.7.0 converged at 7.825 %.
  `solver="trf"` converges at 7.838 %.
  WP-1953 owns the fix.
- Under LM a fit keeps the Gaussian width real at every reflection, Γ_G² ≥ 1e-8 deg², and keeps a Stephens strain block inside its physical range.
  `RESOLUTION_NOT_POSITIVE` and `STEPHENS_STRAIN_NOT_POSITIVE` still fire under `solver="trf"` and in a joint fit.
  Round-robin brucite with a Stephens block now ends inside that range, at χ²_red 7.72, where 1.7.0 reached 7.64 outside it.
- The acceptance suites were re-measured for this release (macOS arm64, `[dev,jax]`), and these answers moved by more than 1 %.
  On NIST SRM 660c LaB₆ the Gaussian width is now real at all 60 reflections, where TRF's answer had it on its clamp at 12.
  The cell reads 4.156882(21) Å, 25 ppm above the certificate, where it read 4.156895(21) Å, 28 ppm above.
  Rwp rises from 8.67 % to 8.75 %.
  The specimen displacement moves from −0.0801 mm to −0.0791 mm.
  With a holder doublet injected into that pattern, ignoring the doublet shifts the cell by +9.9 ppm, where it shifted it by +7.6 ppm.
  Declaring it leaves −1.4 ppm, where it left −1.0 ppm.
  Excluding it leaves +0.2 ppm, where it left +0.6 ppm.
  These SRM 660c moves come from the Γ_G² inequality, since LM without it lands where TRF did.
  At 150 K, above Cr₂WO₆'s ordering temperature, its unsupported moment ends at 0.017 ± 1.29 μ_B under LM, where TRF left it at 0.067 ± 0.83 μ_B.
  Both read as no moment.
  Seeded along a and along b, the 4 K Cr₂WO₆ moment now agrees to 2.4e-8 μ_B, where it agreed to 3e-6 μ_B.
  Chained, the eight round-robin sample 1 patterns take 278 iterations against 1015 fitted one at a time, where they took 725 against 1826.
  On corundum the Stephens block's anisotropy ratio reads 1.52×, where it read 2.03×, at the same χ²_red of 2.65601.
  That ratio rides a flat direction of the Lorentzian split.
  Under `solver="trf"`, round-robin brucite with a Stephens block stops at its iteration limit at Rwp 18.09 %, where it reached 17.84 %.
  Its ΔBIC for the block falls from +22.4 to +9.2.
  Across four starting seeds it leaves the cone on 13, 7, 26 and 24 of 43 reflections, where it left it on 14, 7, 0 and 0.
  The constrained LM fit, at 17.94 %, is now the better of the two by Rwp.
  Corundum's two descriptions of its R lattice now agree to 4.9e-9 in c, where they agreed to 1.5e-8.
- Caglioti `w`'s lower bound is 1e-8 deg², where it was 0.
  A stored `w` below that is raised to it on read, as March `r` is raised to its floor.
  `read_gsas_prm`, `read_gsas2_instprm` and `read_recipe` raise a W between 0 and 1e-8 deg² to 1e-8 in the same way.
- A parameter that ends on a lower bound of 0 reports `FLOOR_HIT` (warning), and keeps its esd (WP-1938, WP-1929).
  Before, a softplus row there was set aside as untested, and its `RefinedParameter.at_bound` read `None`.
  `FLOOR_HIT` says the data push the parameter below zero, and to fix it at 0.
  `BOUND_HIT` said to widen the bound, which a scale or a width cannot use.
  `GuardFinding.limit` carries the bound the finding chose.
  Freed on SRM 660c, extinction now ends at exactly 0, where it ended at 5e-10.
- Under the default LM driver, `at_bound`, `BOUND_HIT` and `FLOOR_HIT` read the driver's active set (WP-1929).
  A row is on its bound when the step landed it exactly there and the data still push it outward.
  Under `solver="trf"` the test is unchanged: within a hundredth of an esd of the limit, and pushed outward.
  A row whose esd was wide enough to reach a limit it was nowhere near is no longer flagged.
- The finite-difference step for the Caglioti `u` and `v` is now sized by their unit, 1e-6 deg², instead of by 1 (WP-1936).
  On a sharp instrument the old step was a large part of the peak's own variance, and on 11-BM SRM 660c it put 8.8e-4 of error into `u`'s Jacobian column.
  Every fit that frees `u` or `v` can move.
- A stage's `seed` lifts only a free row that sits exactly on a lower bound of 0 or more.
  In 1.7.0 it lifted any softplus row below the seed.
  `StageResult.seeded` lists what each stage lifted and the value it started from.
  Of the presets, only the roughness stage seeds now.
  The extinction stage of `mccusker_structural` and the `magnetic_width` preset no longer do.
  That moved no measured value by more than 3.4e-8 esd for extinction and 2.3e-6 esd for the magnetic width.
- A series no longer seeds a warm start, whichever rung runs it.
  A value its neighbour left on a floor was lifted to the plan's largest seed, 0.3 wherever the roughness stage is in the plan.
  On a four-pattern LaB₆ ramp that put a converged Lorentzian width at 0.3°, and the pattern ended at χ²_red 1.0583 against 1.0514.
- `solve_magnetic` frees each trial's moment sizes before their directions, in a stage of their own ahead of the two it ran (`SOLVE_STAGE_NAMES`).
  A small moment's direction barely moves the pattern, and LM gave it the largest steps.
  On a simulated two-site Pnma pattern the start released from one site stopped at χ² 454 660, where 2556 was reachable, and still reported `converged`.
  Every solve can move.
  The nuclear reference does not, since its stages are unchanged.
  A plan you pass is used as it is.
- A moment angle at a direction the site symmetry fixes no longer sets the other esds (WP-1929).
  The pattern is even in the angle there, so its Jacobian column vanishes.
  Where the solver stopped beside it then decided the esd of every parameter correlated with it.
  After each solve the fit tests its free moment angles and leaves those at such a direction out of the covariance.
  Each keeps its value and has no esd, and `MOMENT_ANGLE_STATIONARY` names it.
  On a simulated two-site Pnma pattern with both moments along a, the moduli now read 0.0015 and 0.0011 μ_B with ρ −0.24, and no pair is named.
  Before, under LM, they read 0.031 and 0.159 μ_B, and the two sites were named a `MOMENT_PAIR_DEGENERATE` pair.
  No fitted value moves.
  In the magnetic acceptance suites 7 of 28 fits lose an angle's esd, and their moduli esds fall by 10-60 %.
  `StageResult.moment_angle_tests` records each round of the test, and `Refinement.profile_interval` gives such an angle an interval.
- The hold of a moment direction the powder cannot see turns the moment both ways (WP-1929).
  A one-way turn from 0.05 rad off a symmetry direction lands on the start's mirror image, which reads as flat.
  On a simulated one-site pattern the one-way turn held a determined polar angle at its start, and the fit ended at χ² 20614.
- `suggest()` scores a width on its floor where it is, no longer from a seed of 1e-3.
  The seeded probe ranked such widths first, and freed and refitted each stayed on its floor.
  On BT-1 the list now leads with an occupancy, whose predicted gain of 947 a refit realises as 946.
- The LaB₆ + cBN validation row holds the instrument's Gaussian widths, so its published QPA is 17.791 ± 0.319 wt %, no longer 17.874 ± 0.314.
- An indexing candidate in the monoclinic system is reported in its conventional setting (WP-1923, issue #779).
  That is b unique, a and c the shortest translations normal to b, and β obtuse.
  1.7.0 kept the setting its engine reached, so one lattice could come back as β = 81.78° where its conventional β is 98.22°.
  `cell`, `cell_esd` and `af` all move.
  Grades, ranks and Le Bail fits do not.
- A Niggli-reduced cell is the exact image of its input under its change of basis (issue #797).
  Inside its tolerance the reduction could give a near-zero entry either sign.
  That left one triclinic cell 1.2e-5 off, and a dedup χ² can move by that much.
- `pick_peaks` recognises a resolved Kα2 maximum as an alias when the pattern's step is coarse against the peak width ([#880](https://github.com/yue-here/rietx/pull/880) by @mustachefeeling, issue #878).
  The screen compares two channel positions, so it now allows one step beyond its 0.3 FWHM.
  Where a FWHM spans fewer than about 3.3 channels, the old tolerance was smaller than that error, and high-angle Kα2 maxima came back as lines of their own.
  A Cu Kα rock salt on the preset profile at a 0.02° step indexed 7 of its 9 lines and was graded `low` on `indexed_fraction_low`.
  It now offers 7 lines, and the cF cell indexes all of them.
  A peak list from any doublet source can lose such lines.
  On the IUCr CPD round-robin cpd-4 pattern the usable count goes from 77 to 76.
- `capabilities().indexing_thresholds_version` is `1.9`, where 1.7.0's was `1.7`.
  1.8 marks the monoclinic setting, and 1.9 the alias screen.

### Files that change

A CIF written by `Structure.to_cif`, `Refinement.write_cif` or
`write_refinement_cif` states more, and two of its items change name
(WP-1319). Old CIFs, ours included, still read.

- Displacements are U (`_atom_site_U_iso_or_equiv`, `Uiso`/`Uani`), no longer B.
  The GSAS-II phase CIF keeps B, since GSAS-II's importer reads B.
- The space group is `_space_group_name_H-M_alt` (the resolved setting) with
  the Hall symbol, IT number, crystal system and the full operation loop. The
  deprecated `_symmetry_space_group_name_H-M` is no longer written, except in
  the GSAS-II phase CIF.
- New: the CIF 1.1 magic line, `_audit_*` and `_audit_conform`, an
  `_atom_type` loop, site multiplicities, the formula, Z, Mr, the calculated
  density and the cell volume.
  `_audit_creation_date` is the day of writing, so two writes of one structure
  on different days differ.
- A Le Bail or Pawley refinement CIF states no formula, Mr, density or Z, since
  its one atom is a placeholder. Its sites carry `_atom_site_calc_flag dum`.
- A number without an esd is written as the shortest text that reads back as
  the same double, where it was four or six decimals. A β of 90.00004 and an
  occupancy of 0.33333 now survive a round trip. `write_gsas2_phase_cif`
  writes its numbers the same way.
- Two phases whose names collapse to one block name (`ph 1`, `ph-1`) get
  distinct blocks, `data_ph_1` and `data_ph_1_1`. They used to raise gemmi's
  bare `RuntimeError`.

A script that reads those two old tags out of a file this build wrote needs
the new ones.

The refinement CIF's pattern block is rewritten (WP-1933). `read_pdcif` reads
both the old and the new form.

- The profile loop holds every measured point, where it held the fitted ones.
  `_pd_proc_ls_weight` is 0 on each point the fit did not use, and
  `_pd_proc_info_excluded_regions` names the stretches.
- The grid is `_pd_meas_2theta_scan`, no longer `_pd_proc_2theta_corrected`,
  since nothing corrects it. The intensities are `_pd_meas_counts_total`, or
  `_pd_meas_intensity_total` with the file's σ in parentheses, no longer
  `_pd_proc_intensity_total`. The undefined `_pd_proc_intensity_total_su`
  column is gone, and the fit's σ is in the weights.
- New: `_pd_proc_d_spacing`, the measured and fitted ranges and point counts,
  a wavelength loop with every emission line's weight, the probe, the method,
  the instrument geometry, the restraint count, `_refine_ls_shift/su_max`, the
  absorption correction, extinction on the phase's block, f′ and f″ in the
  `_atom_type` loop, a `_refln` loop, `_cell_volume` with its esd, and
  publication flags and `_geom_special_details` on the geometry loops.
- The profile and background functions are text with an esd on every value,
  in lines of at most 80 characters. The profile text names the shape the fit
  computed. Before, it said TCHZ for a Voigt fit.
- A geometry row whose symmetry code cannot be written is left out and
  counted, where it was written with `?`.

A script that reads the old pattern tags out of a file this build wrote needs
the new ones.

Saved projects, history logs and `.rxt` documents no longer carry a
parameter's `transform` (WP-1938). Old ones open with the same meaning: a
stored `softplus` or `exp` reads as a lower bound of 0, and `logit` also as an
upper bound of 1. A `.rxt` document's `softplus` and `logit` flags are read
and no longer written.

### Requirements that rise

- rietx needs spglib 2.8 or later, where it accepted 2.4.
  spglib 2.8.0 corrects three magnetic space groups (UNI 282-284) that 2.7.0 could not identify from their own operators.
  Every one of the 1651 groups now round-trips.
  Some magnetic candidates that came back unnamed now carry a BNS number.
- `operators.UNI_NOT_IDENTIFIABLE` is gone, since no entry fails to match itself any more.

### The compiled kernels are a wheel

- rietx depends on `rietx-kernels`, its compiled kernels in Rust, and no longer on numba.
  A fresh install's packages take 182 MB, where 1.7.0's took 321 MB, and its first fit compiles nothing.
  numba held numpy below 2.6, and that ceiling is gone.
- An Intel Mac can install rietx again.
  numba has shipped no macOS x86_64 wheel since 0.63, which was rietx's floor.
- `rietx-kernels` has wheels for Linux x86_64 and aarch64, macOS arm64 and x86_64, and Windows x64, on Python 3.11 or later.
  It has no source distribution, so pip refuses to install rietx anywhere else, such as on musllinux or a free-threaded 3.13t or 3.14t.
  numba had wheels for the free-threaded builds.
- From `rietx-kernels` 1.2.0, the two kernels that draw asymmetric peaks use a port of SLEEF's exponential on x86-64.
  They hold it to 1.0 ulp, where 1.1.0 held it to the bit.
  On GitHub's Linux runner the trigger fit takes 15.97-16.10 s, where 1.1.0 took 20.92-21.29 s.
  A slow test fits two patterns on both paths and holds the kernels' answer within 5 esd of numpy's.
  On Linux the gap was 0.42 esd.
  The arm64 wheels keep 1.1.0's code and its bits.
- A kernel call splits across the thread pool once its estimated work reaches 100 µs.
  In 1.7.0 a call needed 512 rows, and the largest call of a trigger-shaped fit had 494, so it never split.
  The split cannot change an output.
- Nothing writes `~/.rietx/numba-cache` any more, and it can be deleted.
- The structure figure's rasteriser is in `rietx-kernels` from 1.1.0, so rietx requires 1.1 or later.
  Its pictures match the numpy path's to the bit, as numba's did.
  On the NAC cell at 400 px, `view="auto"` takes 90-107 ms, where numba took 92 ms.
- The dichotomy indexing engine runs on numpy alone.
  An indexing search on a real pattern takes 3-9 % longer.

### Refusals that are new

The CIF writers refuse, by name and before any file is written, a non-finite
number. They also refuse whitespace or an empty string in any item the CIF
dictionary types as a single word: a site label, a species, a disorder
assembly or group, a moment label, a geometry label. Each wrote a file no CIF
reader could parse.

## New

### Rigid bodies

- `RigidBody.torsions` turns declared atoms of a body about the line through two of its atoms, as TOPAS's `Rotate_about_points` does ([#823](https://github.com/yue-here/rietx/pull/823) by @mustachefeeling, WP-1808).
  A `BodyTorsion` has a `name`, an `axis` of two body atoms, the atoms it `moves`, an `angle` in degrees, and `vary`.
  The moved atoms are declared, not derived from bonds.
  Torsions apply in list order, so a later axis may ride on atoms an earlier one moved.
  Free one with `vary=True` or the path `phases.*.rigid_bodies.*.torsions.*.twist`, and it refines with an esd.
  `add_body` takes `torsions=`.
  A repeated name, an axis that is not two different body atoms, a torsion that moves nothing or moves an axis atom, and a zero-length axis are refused by name.
  On a planted 30° biphenyl twist the fit returned 29.93° with an esd of 0.054°.
- `Refinement.check_rigid_bodies(data)` asks whether the data want a rigid body to be a different shape ([#822](https://github.com/yue-here/rietx/pull/822) by @mustachefeeling, issue #775).
  It refits each body twice from the fitted state.
  One fit keeps the body, and the other frees its atoms, held near the template by restraints on every bond and bonded angle.
  A body fails when the freed fit wins on both Hamilton's test at p < 0.001 and ΔBIC > 10, and the result carries `RIGID_BODY_MISFIT` (warning).
  The message names the three bonds or angles the freed fit moved most.
  It needs a fitted `Refinement`, and `fit()` does not run it.
  On a synthetic small molecule with one C–C bond 0.3 Å too long, the wrong body fitted at GOF 2.33 against 1.01 for the right one, and nothing in 1.7.0 named the body.
- Rigid bodies stay provisional, now with torsions and the check.
  Riding hydrogens and a fragment library are still to come.

### Elsewhere

- `Refinement.profile_interval(data, path)` returns a `ParameterInterval`, the profile-likelihood interval for one refined parameter (WP-1929).
  It pins the parameter, refits the rest, and finds where χ² has risen by a χ²₁ quantile scaled as the esds are.
  For a row on its bound the interval is one-sided.
  That is the number to quote for a width or a scale on 0.
- `rx.report.cumulative_delta_chi2(a, b)` says where along 2θ one result improves on another ([#904](https://github.com/yue-here/rietx/pull/904) by @mustachefeeling, issue #219).
  It returns Σ(δ²_b − δ²_a) against 2θ, and equal-count 2θ quantiles that each carry their Δχ² and share of the total.
  `rx.report.split_localisation(higher, lower)` compares a model with a lower-symmetry one.
  It gives the Δχ² share on the reflections the lower model splits, on those it does not, and on the rest, each beside its share of points.
  Neither sets a threshold or raises a diagnostic.
- `rietx events <events.jsonl | run dir>` summarises an event log run by run ([#902](https://github.com/yue-here/rietx/pull/902) by @mustachefeeling, issue #207).
  It counts fits, stages and evaluations, and gives the seconds per stage name, the termination histogram, the held paths, and the first and last Rwp.
  `--json` prints it as an `EventsSummary`, and `rietx.history.summarize_events` is the function behind it.
- `RefinementResult.cell_volumes` holds one `CellVolume` per phase, in every mode (WP-1933).
  It carries `phase_index`, `volume`, `stderr` through the cell covariance, and `stderr_diagonal` without the correlations.
- `write_refinement_cif(pattern=)` writes every measured point.
  `Refinement.write_cif` passes the pattern the fit was given.
- `ReflectionRow.phase_index`, a phase link that holds where two phases share a name.
- `read_pdcif` reads an su written in parentheses on the intensities.
- `read_gsas_prm(..., profile_set=N)` reads one of several profile functions a bank offers side by side, as `PRCF1`, `PRCF2` and so on.
  Without it set 1 is read, as GSAS-II reads it.
  A file offering more than one reports `GSAS_PRM_PROFILE_SET_DEFAULTED` (warning) into a `diagnostics=` list.
  A refused set 1 names any type-3 set the file states.
  GSAS-II's `BT1_Cu311.inst` offers types 1, 2 and 3, and its refusal now names set 3.
  Set 3 of that file is still refused, at its non-zero `ICONS ZERO`.
- `capabilities().compiled_kernels_unavailable` says why the compiled kernels did not load here, and is `None` when they did.
  `features["compiled_kernels_active"]` is `False` whenever they did not load.
  In 1.7.0 it could read `True` after a failed build.
- `select_chebyshev_order` reports `BACKGROUND_ORDER_AT_CAP` on `BackgroundSelection.diagnostics` when it returns `max_order` without the Durbin-Watson stop ([#871](https://github.com/yue-here/rietx/pull/871) by @mustachefeeling, issue #833).
  The finding names the cap and the last d.
  `auto_background(kind="chebyshev")` passes it on as a `UserWarning`.
  On the 11-BM Si 640c pattern the default returns its cap of 16, as it always did, and now says so.
- `CellCandidate.engine_cell` is the cell in the setting the indexing engine found, and `CellCandidate.change_of_basis` the integer matrix taking it to the reported one.

## CIF files checked against checkCIF

A structure-only CIF from `Structure.to_cif` now reports the same volume,
symmetry, formula, Mr, density and Z that IUCr checkCIF computes. Before, it
reported none of them, and checkCIF skipped its consistency tests for want of
the operation loop. Its remaining alerts ask for single-crystal and instrument
items a powder structure does not have (WP-1319, issue #756).

On a refinement CIF from `Refinement.write_cif`, the alerts for the
shift/su, for lines over 80 characters and for a volume without its esd are
gone, and f′ and f″ are stated (WP-1933). Its A alerts on the FAP and NAC test
files are the same single-crystal and instrument items.

## Changed

- The agent skill's API index is split in two.
  The readers and writers for TOPAS, FullProf, GSAS, GSAS-II and PowderLine files
  are in `references/api-io.md`, and the rest stays in `references/api.md`.
- An install whose compiled kernels do not load warns once, says why, and runs the numpy path.
  Before, it ran the numpy path in silence.
  `RIETX_COMPILED=0` chooses the numpy path and silences the warning.
- A result's stage summary says `(10 evals, …)` where it said `(10 it, …)`.
  `StageResult.n_iterations` has always counted residual evaluations, and the manual now says so.
- `read_pdcif` takes σ only from the su column of the intensity column it read.
  1.7.0 took the first su column it found, so a file stating a processed intensity and only a measured intensity's su got σ from the measured column.
  Such a file now falls back to its weights or to counting statistics.
- The matplotlib floor drops from 3.10.5 to 3.10 on Python 3.11 to 3.13.
  Python 3.14 keeps 3.10.5, the first release with wheels for it.
  Google Colab preinstalls matplotlib 3.10.0 and imports it at startup.
  Under the old floor, `%pip install rietx` upgraded it and Colab asked for a
  runtime restart before the tutorial's next cell.

## Magnetic structures

- `analyse` proves more pairs of magnetic candidates without drawing a pattern ([#853](https://github.com/yue-here/rietx/pull/853) by @mustachefeeling, issue #565 part 4).
  A candidate family is proved contained in another when its shell intensities are the other's through one fixed map of amplitudes and one scale (`span`).
  The measured case is a rank-1 direction inside its irrep's rank-2 plane.
  A proved separation is carried along each proved containment (`containment`).
  It is also carried to a third family that reproduces the same draw (`transfer`).
  The candidate table prints the residual of each containment, and the cosine and bound of each transfer.
  On the `F -4 3 m` Γ set, one stored draw of S4 separates every S4 family from S5(rank 2) and its sub-family.

The isotropy machinery (`rietx.crystallography.magnetic.isotropy`) is internal, and may change in any release.
