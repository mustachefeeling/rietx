# rietx 1.2.0

**The GUI milestone.** `rietx gui` stopped being a beta feature and became the
half of the package a crystallographer meets first: one control vocabulary
instead of five, one mechanism for explaining a name, example projects that
open from a blank state, a plot whose axes hold still while you work, and a
Model panel where the refinement flags sit beside the values they govern. It is
[documented](https://rietx.org/using/gui-quickstart.html) in three manual
chapters whose routes, panel names and screenshots are guarded by tests, so the
prose fails the build when the app moves.

The release carries a second half the milestone did not plan. Between 1.1.0 and
here, contributed work added **constant-wavelength neutron support**, declared
**background peaks**, two-tier **soft caps** on sample strain and size, three
GSAS reader repairs, and several new diagnostics. Those are the changes that
move numbers, so they are listed before the GUI below, and § Upgrading says who
has to act.

## Install

```sh
pip install --upgrade rietx
```

Nothing about the dependency set changed in this release. numba is still a core
dependency carrying the compiled kernel tier (`RIETX_COMPILED=0` switches it
off at runtime), and its `numpy<2.6` ceiling is still the package's.

## What a fit answers differently

Five changes reach a fit a 1.1.0 user is already running. Each is opt-out or
inert on data it was not written for, and none is a change to the forward model
a converged fit was already using.

- **Sample strain and size broadening are bounded, and a surprising value is
  flagged.** Fitting 248 patterns of a CuO→Cu reduction series, `lor_strain`
  ran past 1 in 133 of them and peaked at 1.1e5 — a line wider than the
  pattern — which starved a genuine 16 wt % phase below 1 wt % in 195 rows and
  inflated weight fractions ×1.19. Two tiers now answer that, and they do
  different jobs. **Tier 1 is a solver bound derived per pattern from the
  fitted 2θ range** (`params.vector.strain_cap` / `size_cap`), on the statement
  that a line wider than the interval it was measured over is not a line; on a
  normal lab scan it sits 278× above the strain a TOPAS protocol would allow,
  because a bound on how strained a specimen may be would prejudge the physics.
  It is enforced per stage, not per iteration, and it reports itself through
  `BOUND_HIT` and `at_bound`, which already existed. **Tier 2 bounds nothing
  and says a number is surprising**: `STRAIN_UNUSUALLY_LARGE` above 1.5 deg and
  `SIZE_UNUSUALLY_SMALL` below 5 nm apparent crystallite, both calibrated
  against an archive of 606 solved TOPAS refinements rather than chosen. A fit
  that stays under the caps is **bit-identical** — all 33 parameters, Rwp, GoF
  and every per-stage iteration count identical on the FAP acceptance protocol
  — and any finite `Parameter.max` you set is your own claim and outranks both
  tiers.
- **Three GSAS reader defects, two of which returned wrong patterns.** An ESD
  bank is a fixed-width record, and reading it by whitespace merged adjacent
  fields: three of 34 recovered 11-BM pattern files raised
  `could not convert string to float: '298.5101641.3'` and now parse. Worse
  than a refusal, the `bintype` and the type flag were read as one declaration,
  so 18 real files gathered from six sources — GSAS-II's own tutorial data
  among them — returned *plausible wrong patterns*, one ISIS PEARL bank
  arriving as a flawless-looking 2528-point scan from 15.00° to 194.88°. Those
  now refuse by name. And a `BANK` record sitting behind a 71-row `TIME_MAP`
  table (the GSAS distribution's own `example/vnb5053.dat`) is sniffed as GSAS
  instead of falling through to the `xy` catch-all.
- **A capillary with no goniometer radius says so.**
  `CAPILLARY_OFFSET_UNAVAILABLE` (info) fires when the eq (4) position offsets
  were held at zero for want of a radius. An unmodelled offset moves every axis
  by the same fraction, so an axial ratio can agree to a few ppm while no axis
  does — 143 ppm on both Cr₂WO₆ axes with c/a agreeing to 3.4 ppm. On a
  calibrated synchrotron this is a note; on a laboratory capillary it is a real
  accuracy gap.
- **A refined wavelength is measured against the wavelength you declared**
  (WP-1134). The declared λ is a construction fact carried through branches and
  stages rather than a per-call one, so a second λ-freeing fit reports its
  cumulative move (`WAVELENGTH_CALIBRATION`, in ppm) from the value someone
  actually declared instead of from the previous call's answer.
- **The extinction screen no longer warns its way through a Laue branch.** Each
  branch is clamped to its own domain rather than to zero. Verified
  bit-identical on every consumed point (0 of 60 004 differing) and
  warning-free under numpy's default errstate, so no answer moves.

## What a fit can now do

- **Constant-wavelength neutrons.**
  `Instrument.constant_wavelength_neutron(...)` builds a `NeutronSource` — the
  nucleus is a point scatterer, so *b* replaces f₀ and there is no anomalous
  dispersion — and a monochromator's λ/n contamination is declared rather than
  ignored (`Source.harmonics`, with `HARMONIC_HELD` / `HARMONIC_ABSENT` /
  `HARMONIC_FRACTION` reporting what the fit could say about it).
  `capabilities().radiations` is where a program reads which radiations this
  build knows. The wavelength itself is refinable: `EmissionLine.wavelength`
  and `NeutronSource.wavelength` are `Parameter` objects now, so a certified
  cell held fixed turns a free λ into a calibration measurement (the Si SRM
  640c acceptance suite does exactly that).
- **Declared background peaks.** `Instrument.background_peaks` takes explicit
  broad Gaussians for a diffuse hump, an amorphous component or a
  sample-environment contribution, instead of making the polynomial flexible
  enough to contort into one. Three free parameters with an unconstrained
  position is a reflection with no cell behind it, so the feature carries its
  own fence: `BACKGROUND_PEAK_TOO_NARROW` fires when a declared peak narrows
  toward the instrumental resolution, and
  `RefinementResult.n_background_peaks` / `BackgroundEvidence.n_peaks` say how
  many were declared.
- **A width read as a crystallite size.** `apparent_size`,
  `apparent_size_from_size_coefficient` and `size_coefficient_for_size`
  (`rietx.model.profiles.caglioti`) convert between a size coefficient and a
  size, because a 1/cosθ coefficient maps to one size across the whole pattern
  with no reference angle. The FitReport's sample-broadening action quotes the
  size beside the coefficient, so the judgement transfers between instruments.
- **A per-phase agreement trajectory across a series.**
  `SeriesEntry.phase_agreement` carries each pattern's own R_Bragg / R_F over
  the series boundary, and `SeriesResult.agreement_trajectory(phase, metric=…)`
  gives it `qpa_trajectory`'s shape. Watching one phase's index move across a
  ramp is what a series can show and a single fit cannot. Every `stderr` in
  that trajectory is `None`, and that is a fact rather than a gap: a residual
  is not a fitted parameter and has no covariance entry to propagate from.
- **Two model-free pre-fit measures** in `background.diagnostics`: an end of
  the range where the signal collapsed, and one where the σ column says fewer
  detectors were watching. They look alike and are not — the first must be
  excluded and the second kept — and a dead tail corrupts the very checks a
  caller would use to choose a background (measured on ILL D20 SrFeO₃: the
  air-scatter score understated 53×, the spline stiffness selection 100× off).
  Both are descriptive; nothing is trimmed automatically.
- **A project can hold no phase at all.** A pattern is already a project: peak
  picking, indexing and the parameter table work over it, and only refining is
  refused — by the verb rather than by the schema, since a validator would take
  the routes out with it. `NoPhasesError` (agent code `NO_PHASES`) is a fourth
  envelope code, because the request is well formed and the model is legal.
  What is missing is a cell.

## The GUI

`rietx gui [PROJECT.rex]` is documented and out of beta. What a first-time user
meets:

- **A project from nothing.** The empty state lists the example projects that
  ship in the wheel (real specimens, each one a validation standard) and
  browses the machine for an existing one. A new project needs a pattern; a
  structure is optional, and where there is no CIF the wizard takes a
  space-group symbol and the cell parameters that *setting* leaves free, or
  nothing at all.
- **One vocabulary, one help mechanism.** Every control comes from one token
  layer and nine registers rather than from five ad-hoc geometries. A click on
  almost any term opens one popover with the name's description, unit, default,
  typical range and a link into the manual — keyboard-reachable, which a
  `title=` tooltip never was. The corpus behind it is `rietx.help`, 119 entries
  over nine vocabularies, each crossed against the live schema in both
  directions, and it also generates the manual's
  [glossary](https://rietx.org/using/glossary.html).
- **A plot that holds still.** A redraw never moves the axes: hover, unhover, a
  tab change and a whole exclude drag now change nothing a person did not
  change. The hover tooltip that covered the data is gone, replaced by a strip
  under the plot that also says which reflection of a proposed cell sits under
  the pointer, on which emission line, and at what d.
- **Peaks and candidates you can see.** The peak layer has its own colours, its
  own tab and a way off; an indexing candidate's predicted lines draw over the
  pattern that has to answer them; and the peak table reads like a peak table —
  relative intensities, four places of 2θ, chips that say words.
- **The Model panel is an editor.** Refinement flags sit beside the values they
  govern and land as `set_vary` history nodes; an atom is one row with typed
  x, y, z (refused, never snapped, when the site symmetry cannot reach the
  position asked for); the instrument is a form of three groups with U V W
  above X Y; and a calibrated instrument profile can be saved from the GUI, not
  only loaded.
- **A history graph that reads like a git graph**, and a compare table whose
  numbers hold their columns, each parameter family declaring its own place
  count.
- **`rietx gui --scratch`** opens a byte-for-byte copy in a temp directory,
  because opening a project writes to it. `--state-dir` puts the recent list
  somewhere you choose.

The GUI's **routes stay provisional by declaration** — the wire is the half
that still moves — and that is stated in
[compatibility](https://rietx.org/using/compatibility.html) rather than implied.

## Contract versions

Six versioned contracts, and `capabilities()` is where a program reads them
rather than this table. Three moved since 1.1.0:

| Contract | 1.1.0 | 1.2.0 |
|---|---|---|
| `schema_version` | 0.5 | **0.10** |
| `report_thresholds_version` | 1.3 | **1.4** |
| `project_format_version` | 1.2 | **1.3** |
| `indexing_thresholds_version` | 1.3 | 1.3 |
| `event_schema_version` | 2 | 2 |
| `textdoc_format_version` | 1 | 1 |

`schema_version` moved five times, and each step's comment sits beside the
constant in `schemas/common.py`: 0.6 added `SeriesEntry.phase_agreement`; 0.7
is constant-wavelength neutron support (the `NeutronSource` arm, `harmonics`,
and the wavelength becoming a `Parameter`); 0.8 added `ParameterRow.help_key`;
0.9 let `Structure.phases` be empty and brought `NO_PHASES` with it; 0.10 added
`Instrument.background_peaks` and `RefinementResult.n_background_peaks`. None
of the five changes what an existing document means, and every document written
by 1.1.0 validates unchanged.

## Upgrading

Who has to do something, and what.

- **You refine sample broadening free** (`lor_strain`, `gauss_strain`,
  `lor_size`, `gauss_size` — `lab_sample_refine` frees all four). They now
  carry a per-stage bound derived from the fitted 2θ range, and two new
  diagnostics can fire. A fit under the caps is bit-identical; a fit that was
  running away is not, and that is the point. Set any finite `Parameter.max` on
  the term to take the decision back — including a deliberately enormous one,
  since `±inf` is what says nobody made a claim.
- **You read GSAS `.raw`/`.gsas`/`.fxye` files.** Files that raised on an ESD
  bank now parse. Files whose bank declaration the reader used to misread now
  **refuse by name** rather than returning a plausible pattern — if a pipeline
  of yours quietly consumed one, its results were wrong and are worth
  re-running. A `BANK` behind a `TIME_MAP` table is now claimed by the GSAS
  reader rather than the `xy` catch-all.
- **You switch exhaustively on `Instrument.source.kind`.** There is a second
  arm, `"neutron_cw"`. `capabilities().radiations` enumerates what this build
  supports.
- **You read a serialized source.** Every source now carries a `harmonics` list
  (empty by default, and refused outright on an X-ray source), and
  `EmissionLine.wavelength` / `NeutronSource.wavelength` are nested `Parameter`
  objects where they were bare numbers. Both still *accept* a bare number on
  construction and default to `vary=False`, so only readers of the serialized
  form are affected. A neutron source carrying a harmonic reports more than one
  entry in `source.lines`, since the λ/n lines are derived there.
- **You index `structure.phases[0]`, or count phases to size an answer.** A
  structure may now legally hold none. The verbs that need one (`fit`,
  `run_stage`, `refine_multi`, `refine_sequential`, `POST /api/run`) raise
  `NoPhasesError` before a tree is built or an event emitted.
- **You branch on `AgentError.code`.** `NO_PHASES` is a fourth member. Retrying
  will not help it: the model has no cell, so index one or supply one.
- **You enumerate diagnostic codes.** Eight are new: `STRAIN_UNUSUALLY_LARGE`,
  `SIZE_UNUSUALLY_SMALL`, `BACKGROUND_PEAK_TOO_NARROW`,
  `CAPILLARY_OFFSET_UNAVAILABLE`, `WAVELENGTH_CALIBRATION` and the three
  `HARMONIC_*` codes (`NO_PHASES` is an envelope code, not a diagnostic — a
  refused fit produces no result to carry one). The first two are the only rows in
  `AGENT_PROTOCOL` § 7 that ask a reader to *adjudicate* a number rather than
  withhold it.
- **You consume `ParameterRow`.** It carries `help_key`, the help-corpus family
  glob that describes the path (`None` where no family claims it). The row
  holds the key rather than the entry on purpose: inlining the entry repeats a
  paragraph once per atom, 3.4× the payload measured.
- **You save a `.rex` project here and open it with 1.1.x.** The project format
  is 1.3. `project.json` itself is unchanged; what moved is one rank down, in a
  `history.jsonl` state whose zero-phase structure an older build's validator
  refuses to construct. The major gate still opens every 1.x.
- **You depend on a GUI route.** The routes are provisional by declaration and
  may change in any release. The panels, the `.rxt` document and the CLI are
  documented in the usual way.

Nothing else moves a refinement's answer beyond the five entries in § What a
fit answers differently.
