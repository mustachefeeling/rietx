## Upgrading

Code written against 1.9.0 runs unaltered.

### Code to check

- `capabilities().schema_version` is `0.56`, where 1.9.0's was `0.55`.
  0.56 adds `RefinementResult.parametric_form`, and a result carrying it does not open in 1.9.0.

### Numbers that move

- A joint fit with per-histogram phase paths now holds a pattern's own copy of a phase's cell where that pattern cannot see the phase (WP-1325).
  In 1.9.0 the cell stayed free in that pattern whenever another pattern still showed the phase, so it could wander with nothing to fit.
  A fit moves only where a phase is absent from some of its patterns and its cell is per-histogram, as under `SharingMap(per_histogram=["phases.*"])`.

## New

- A joint fit now tests each parametric declaration's form against its own data (WP-1325, schema 0.56).
  `RefinementResult.parametric_form` holds one `ParametricFormTest` per declaration: how much the fit would improve with the target free in each pattern, over the noise level, against the 95 % point for its degrees of freedom.
  It is a score test at the answer and needs no refit; on a 33-pattern real ramp it cost 0.7-0.8 s and gave a full refit's verdict on all five laws tried.
  `str(result)` prints the verdict after each declaration's coefficients, and `PARAMETRIC_FORM_REJECTED` (warning) names the coefficients of a rejected law, whose esds assume the form.
  The test sees a law only where a pattern measures its target, so a law carried through patterns that cannot see a phase is not checked there.
