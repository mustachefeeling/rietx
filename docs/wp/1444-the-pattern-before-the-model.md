# WP-1444 — The pattern before the model, and a title on the figure

Milestone: unscheduled · Status: ⬜
Depends on: —
Priority: P3 2026-09-23 — a figure the user draws by hand today

## Goal

A pattern just read from a file can be drawn in the package's own style before
any model exists, from a script or a notebook, and every result figure can
carry a title the caller chose.

## Context

Two asks from the first week of outside use, both on the figure surface.

**#394 (the maintainer, 2026-09-19): plot imported data without a model.** At
`4ee4e7f5` nothing draws a bare `PatternData`. `viz/plots.plot_result`
(`plots.py:287`) takes a `RefinementResult`; `plot_for_vlm` (`plots.py:669`)
and `plot_trajectory` (`plots.py:761`) likewise take results; the only
function that draws data alone is `viz/indexing.plot_peak_list`
(`indexing.py:74`, `data=` optional), which is the indexing view and marks
peaks. `PatternData` (`schemas/pattern.py`) has `tt()` and `sig()` and no
`plot`, where `RefinementResult.plot` (`schemas/results.py:1285`) forwards
`**kw` to `plot_result`. The new verb is `plot_pattern(data, *, path=None,
two_theta_range=None, x_axis="two_theta", wavelength=None, y_scale="linear",
style="light", figsize=None, font_size=BASE, dpi=300)` in `viz/plots.py`,
built on the same helpers the result panel uses (`_x_values`, `_y_scale`,
`_rc`, `_nice_ticks`) so the two figures are one style, plus
`PatternData.plot(path=None, **kw)` as the peer of `RefinementResult.plot`.
Excluded regions are shaded as the result panel shades them, and σ, when the
file carried it, is not drawn (a √y band on a log axis is a different
figure; not this WP). `plotly` is not touched: the GUI already draws a
pattern with no model, and the HTML renderer (`viz/html.py`) takes a result.

**#405 (a newcomer, 2026-09-20): `result.plot(title=...)`.** No figure
function takes a title. `plots.py:51` states the house rule: "Fit statistics
are a corner annotation, not a title — the caption is the title", which is
the figure-style rule for a paper figure. A notebook cell or a batch of thirty
patterns has no caption, and a figure with no name in it is the reader's
problem there. So `title: str | None = None` on `plot_result`, `plot_pattern`
and `plot_trajectory`, drawn as the axes title in the panel's own font when
given and absent otherwise, so the default figure is byte-identical to
today's. `plot_for_vlm` already sets titles of its own (`plots.py:724`) and
keeps them; a caller's `title` there would prefix the first panel's, or is
refused by name, decided by the session that reads that montage's layout.

**Surfaces that move with a new public verb.** `tests/api_surface.py`'s
partition fails until the verb is documented in Part 1 (`using/data.md` for
the pattern plot, `using/results.md` for the title) or deferred with a
reason; `docs/skill/rietx/references/api.md` is generated by
`make_api_index.py` and pinned byte for byte, so it is regenerated, and the
two installed copies re-synced with `rietx skill --install . --copy`;
`capabilities()` needs no new flag (the `viz` feature flag already exists).
Figures for the manual come from `docs/manual/make_figures.py`, the one
authority, as a committed light/dark pair.

## Non-goals

- A peaks overlay or a peak-finding view: `plot_peak_list` is that, in
  `viz/indexing`.
- Drawing several patterns in one figure (a series stack). `plot_trajectory`
  is the series view, and a waterfall is a figure of its own.
- The HTML renderer and the GUI, which already show a pattern without a
  model.
